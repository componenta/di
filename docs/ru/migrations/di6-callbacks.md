# Переход с версии 5: функции обратного вызова и объединения типов

[Английская версия](../../migrations/di6-callbacks.md)

Для библиотеки требуется PHP 8.4 или новее. Нативные статические замыкания и ссылки на функции, записанные непосредственно в аргументах атрибутов, требуют PHP 8.5. Ранее поддерживаемые способы передачи вызываемых значений сохраняются.

## Преобразование значений через Transform

`#[Transform]` — повторяемый атрибут свойства или параметра. Его конструктор принимает ровно один объект `Closure`.

```php
use Componenta\DI\Attribute\Transform;

// Для такой записи функций в атрибутах нужен PHP 8.5.
final class EmailInput
{
    public function __construct(
        #[Transform(trim(...))]
        #[Transform(static function (string $value): string {
            return strtolower($value);
        })]
        public string $email,
    ) {}
}

$input = $container->make(EmailInput::class, ['email' => ' Alice@Example.COM ']);
// $input->email === 'alice@example.com'
```

`Transform` начинает работу после получения значения из выбранного источника. Сам атрибут не запрашивает преобразуемый параметр из контейнера. Несколько преобразований выполняются в порядке объявления. При совместном использовании `#[Cast]` и `#[Transform]` их относительный порядок также определяется объявлением, если правила сочетания атрибутов не задают иное.

Первый параметр функции получает текущее значение, включая `null` или массив целиком; последующие параметры разрешаются средствами контейнера. Первый параметр нельзя передавать по ссылке, объявлять с переменным числом аргументов либо помечать зарегистрированными атрибутами внедрения зависимостей. Обязательный параметр без источника остаётся неразрешённым; стандартное значение или допускающий `null` тип обрабатываются обычным образом.

## Функции инициализации SetUp и совместимость Init

Атрибут `#[SetUp('initialize')]` по-прежнему вызывает общедоступный метод экземпляра. Свойство `SetUp::$method` дополнительно принимает `Closure`: первый параметр получает создаваемый объект, остальные могут разрешаться через контейнер или задаваться явно в `params:`.

```php
use Componenta\DI\Attribute\SetUp;

// Для статического замыкания внутри атрибута нужен PHP 8.5.
#[SetUp(method: static function (Worker $instance, Formatter $formatter): void {
    $instance->label = $formatter->format('ready');
})]
final class Worker
{
    public string $label;
}
```

Действия `SetUp` выполняются после внедрения свойств. Их возвращаемые значения игнорируются и не заменяют созданный объект. Повторные атрибуты сохраняют порядок объявления. Если наследник повторно объявляет свойство `SetUp::$method` с типом `string`, его необходимо привести к поддержке `string|Closure`.

`#[Init]` сохраняет прежнюю поддержку строк, массивов и вызываемых объектов. Синтаксис PHP 8.5 дополняет существующие способы, а не заменяет их.

## Автоматическое разрешение объединений типов

Если параметр без переменного числа аргументов объявлен с простым объединением именованных типов, служба может быть найдена автоматически по одному из классов или интерфейсов:

| Доступные службы по именам классов или интерфейсов | Результат |
| --- | --- |
| Нет | Применяются обычные правила значений по умолчанию, `null` или отсутствующего аргумента. |
| Одна | Контейнер получает её и проверяет соответствие полному объявленному типу. |
| Несколько | Выбрасывается `ResolutionException` из-за неоднозначности. |

Два псевдонима, ведущие к одному объекту, всё равно считаются двумя доступными идентификаторами. Контейнер не создаёт кандидатов для сравнения их идентичности. Неоднозначность устраняется явным аргументом или атрибутом источника, например `#[EntryId('primary.clock')]`. Пересечения типов и объединения с пересечениями не выбираются автоматически.

## Преобразование данных после чтения запроса

У `MapRequest` появился последний необязательный параметр конструктора `?Closure $afterMap = null`. Первый параметр функции получает весь собранный массив; остальные могут разрешаться через контейнер. Функция должна вернуть массив до создания объекта передачи данных. Проверка исходных данных выполняется раньше, а последующие проверки источников остаются в силе.

```php
use Componenta\DI\Attribute\MapRequest;

// Для ссылки на функцию внутри атрибута нужен PHP 8.5.
function normalizeInput(array $data): array
{
    return ['name' => trim((string) ($data['name'] ?? ''))];
}

$handler = static fn(
    #[MapRequest(afterMap: normalizeInput(...))] CreateInput $input
): CreateInput => $input;
```

Прежние аргументы `MapRequest`, атрибуты отдельных источников запроса, собственные реализации `transform()` и ручная обработка данных остаются доступны.

## Ограничения синтаксиса PHP

В аргументах атрибутов PHP 8.5 допускаются статические замыкания без захвата переменных и ссылки на объявленные функции или статические методы. Стрелочные функции, замыкания с захватом переменных, динамически вычисляемые вызываемые значения и ссылки на методы объектов здесь недопустимы. Обычные вызовы во время выполнения этих ограничений не имеют.

В некоторых исправлениях PHP 8.5 встречается ошибка обработки области видимости при обращении к методам, подключённым с помощью `trait`. Соответствующие формы ссылок на функции проверены на PHP 8.5.13; для более ранних вариантов следует использовать проверенную версию PHP либо подходящее статическое замыкание.

Источники данных HTTP-запроса описаны в [руководстве по атрибутам](../guide/attributes.md).
