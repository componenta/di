# Переход с версии 5: определения и расширения

[Английская версия](../../migrations/di6-definitions.md)

Основные способы работы с контейнером, включая `ContainerFactory`, `get()`, `make()`, `set()` и поставщиков конфигурации, сохраняются. Изменения необходимо учитывать при использовании `ClassDefinition`, собственных обработчиков поиска зависимостей и прямом создании встроенных стратегий.

## Описания создания классов

Вместо `ClassDefinition::method()` используется `call()`. Методы `constructor()`, `call()` и `autowire()` возвращают новое определение, не изменяя исходное.

```php
use Componenta\DI\Definition\ClassDefinition;
use Componenta\DI\Definition\Definition;

$container->set(
    Client::class,
    ClassDefinition::create(Client::class)
        ->constructor(['endpoint' => 'https://api.example.test'])
        ->call('setLogger', [Definition::reference(LoggerInterface::class)])
        ->autowire(),
);
```

`ClassDefinition` не исполняет атрибуты внедрения зависимостей целевого класса и его членов, даже если включён `autowire()`. Поиск по типам применяется только для отсутствующих аргументов. `Definition::reference()` описывает аргумент-ссылку на другую службу, а не самостоятельную запись контейнера. Явные фабрики по-прежнему могут принимать первые аргументы из последовательности `(ContainerValue, array)`.

## Пользовательские стратегии

Регистрациями владеет составной обработчик. Стратегии определений проверяют и исполняют полученные описания, не храня собственных таблиц привязок.

| В версии 5 | В версии 6 |
| --- | --- |
| `DefinitionAwareResolverInterface` | `DefinitionResolverInterface` |
| `new FactoryResolver($factories, $container, $proxyFactory)` | `new FactoryResolver($container, $proxyFactory)` |
| `new InvokableResolver($invokables)` | `new InvokableResolver()` |
| Регистрация внутри отдельной встроенной стратегии | `CompositeResolver::setDefinition()` |
| `resolve(string $id, array $params)` для дополнительного поиска | `resolve(string $id, EntryParameters $params)` |

Реализация `DefinitionResolverInterface` предоставляет `supportsDefinition()`, `validateDefinition()` и `resolveDefinition()`. Выбирается первая стратегия, поддерживающая переданное определение. Проверка возвращает описание для последующего исполнения, но не создаёт регистрацию. Дополнительные способы поиска зависимостей продолжают использовать `EntryResolverInterface`.

`DependencyConfiguration::normalize()` сохраняет объекты определений в разделе фабрик. Нормализация проверяет форму конфигурации, однако сама по себе не подтверждает возможность создания значения. Содержательная проверка выполняется при добавлении определения в контейнер или составной обработчик.

## Передача аргументов при дополнительном поиске

Пользовательский обработчик получает `EntryParameters`; значения доступны через `$params->values`. Метод `$params->forwardTo($factory, $entry)` позволяет продолжить ту же операцию создания с сохранением сведений об источнике аргументов, если принимающая сторона это поддерживает. Передача обычного массива в `make()` начинает отдельную операцию.

Для создания контейнера предпочтителен `ContainerFactory::create($config, $dependencies)`. При прямом вызове конструктора `Container` и создании его внутренних компонентов необходимо учесть новые сигнатуры и правила владения.

## Ошибки регистрации и срок жизни значений

Методы `set()`, `alias()`, `delegator()` и `addContainer()` проверяют и применяют изменения, сбрасывают затронутые сохранённые значения и только затем освобождают заменённые объекты. Ошибка **до** применения сохраняет прежнюю привязку. Исключение `MutationRetirementException` означает, что изменение **уже применено**, но при освобождении старых значений произошла ошибка.

```php
use Componenta\DI\Exception\MutationRetirementException;

try {
    $container->set('example', Definition::factory(
        static fn() => new Example(),
    ));
} catch (MutationRetirementException $error) {
    // Изменение применено: проверьте $error->causes, не повторяйте регистрацию безусловно.
}
```

`MutationRetirementException` наследует `InvalidConfigurationException`, поэтому сначала необходимо обрабатывать более конкретный тип. Свойства `id` и `causes` содержат идентификатор затронутой операции и упорядоченный набор причин. Независимо завершённые вложенные изменения не отменяются.

Отсутствие **запрошенной** записи приводит к исключению об отсутствии значения по стандарту PSR-11. Ошибка при получении зависимости внутри существующей записи относится к ошибкам разрешения.
