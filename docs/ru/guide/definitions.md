# Определения зависимостей

Контейнер принимает готовые значения, фабрики, описания создания классов и классы с конструктором без обязательных аргументов. Если явная привязка отсутствует, он может создать конкретный класс с помощью механизма отражения PHP.

## Готовые значения

Метод `ConfigProvider::getServices()` регистрирует существующие значения. Объекты сохраняют свою идентичность. Допускаются также замыкания, ресурсы, `null` и `false`.

```php
protected function getServices(): array
{
    return [
        ClockInterface::class => new SystemClock(),
        'feature.enabled' => false,
    ];
}
```

Для собственной записи контейнера результат `get()` используется повторно. Метод `has()` проверяет, известна ли запись, но не гарантирует успешное создание значения.

## Фабрики

Фабрика может принимать первые ноль, один или два аргумента из последовательности `(ContainerValue $context, array $params)`. Первый предоставляет контейнер и конфигурацию; второй содержит дополнительные параметры, переданные в `make()`.

```php
use Componenta\Config\ContainerValue;

protected function getFactories(): array
{
    return [
        Client::class => static fn(
            ContainerValue $context,
            array $params,
        ): Client => new Client(
            $context->config->string('api.endpoint'),
            $params['timeout'] ?? 10,
        ),
    ];
}
```

Фабрика полностью отвечает за создание возвращаемого значения. Контейнер не применяет к нему атрибуты внедрения зависимостей после возврата. В `getFactories()` также можно указать идентификатор службы, возвращающей вызываемое значение, отложенную пару `['factory.service', 'create']` или объект, реализующий `LazyServiceFactoryInterface`. См. [справочник определений](../api/definitions.md) и [отложенное создание под управлением фабрики](../api/lazy.md). Метод `Definition::factory()` принимает допустимое вызываемое значение PHP; ещё не разрешённые описания служб следует задавать в конфигурации.

## Описание создания класса

`ClassDefinition` вызывает общедоступный конструктор с настроенными аргументами, после чего последовательно вызывает указанные методы. Поддерживаются ссылки на другие службы и необязательное разрешение отсутствующих аргументов по типам.

```php
use Componenta\DI\Definition\ClassDefinition;
use Componenta\DI\Definition\Definition;

$definition = ClassDefinition::create(Client::class)
    ->constructor(['endpoint' => 'https://api.example.test'])
    ->call('setLogger', [Definition::reference(LoggerInterface::class)])
    ->autowire();
```

Методы `constructor()`, `call()` и `autowire()` возвращают новые определения, не изменяя исходное. Повторные вызовы одного метода через `call()` сохраняются.

По умолчанию используются только заданные аргументы, переопределения конструктора при вызове `make()` и стандартные значения параметров PHP. `autowire()` включает поиск зависимостей по типу класса или интерфейса **только для отсутствующих аргументов**. Явно переданный `null` имеет приоритет. Этот режим не включает обработку атрибутов параметров и пользовательских обработчиков разрешения параметров. `ClassDefinition` вообще не исполняет атрибуты внедрения зависимостей целевого класса, его конструктора, свойств и вызываемых методов.

`Definition::reference()` получает службу из контейнера при разрешении настроенного аргумента. Вложенные массивы таких аргументов обрабатываются рекурсивно; значения, переданные непосредственно в `make()`, не преобразуются. Неизвестные аргументы в настройке конструктора или метода с фиксированными параметрами отклоняются. Циклические массивы настроенных аргументов приводят к `InvalidConfigurationException`.

Явные определения можно добавлять и после создания контейнера:

```php
use Componenta\DI\Definition\Definition;

$container->set('answer', 42);
$container->set(Service::class, Definition::factory(static fn(): Service => new Service()));
$container->set(Utility::class, Definition::invokable(Utility::class));
```

`Definition::factory()` создаёт описание фабрики, а `Definition::invokable()` — описание класса, создаваемого без передачи аргументов конструктору. Регистрация выполняется через `set()` или поставщика конфигурации.

## Классы с созданием без внедрения и псевдонимы

```php
protected function getInvokables(): array
{
    return [
        Logger::class,
        LoggerInterface::class => Logger::class,
    ];
}

protected function getAliases(): array
{
    return [CacheInterface::class => RedisCache::class];
}
```

Класс из `getInvokables()` создаётся без передачи аргументов конструктору; стандартные значения PHP при этом действуют. Атрибуты внедрения зависимостей не обрабатываются. Запись с именованным ключом дополнительно регистрирует псевдоним конкретного класса. Метод `getAliases()` позволяет объявить псевдонимы отдельно. Неудачная попытка создания не сохраняется как готовое значение.

## Обработчики результата

Обработчик получает значение собственной записи контейнера и при необходимости сам контейнер. Обработчики выполняются в порядке поставщиков конфигурации и регистрации.

```php
protected function getDelegators(): array
{
    return [
        Client::class => [
            static fn(Client $client): Client => $client->withMetrics(),
            ['tracing.decorator', 'decorate'],
        ],
    ];
}
```

Пару «идентификатор службы — метод» необходимо вложить в список обработчиков. Иначе два строковых элемента будут истолкованы как два самостоятельных обработчика. Обработка применяется при получении общего значения через `get()`, но не при создании объекта через `make()`.

Подробнее см. [«Интерфейс контейнера»](container.md).
