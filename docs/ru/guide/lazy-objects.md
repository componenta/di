# Отложенное создание объектов и виртуальные заместители

Контейнер использует нативные средства PHP 8.4 для отложенного создания объектов. Метод `makeLazy(string $class, callable $initializer)` создаёт объект с отложенной инициализацией состояния, а `makeProxy(string $class, callable $factory)` — виртуальный заместитель, обращающийся к создаваемому по требованию объекту.

При создании через механизм отражения эти способы выбираются атрибутами класса `#[Lazy]` и `#[Proxy]`. Атрибут `#[Proxy]` также поддерживается в точках внедрения зависимостей.

```php
use Componenta\DI\Attribute\Lazy;

#[Lazy]
final class Catalog
{
    private array $items = [];

    public function count(): int
    {
        return count($this->items);
    }
}

$catalog = $container->get(Catalog::class);
$count = $catalog->count(); // Инициализация выполняется, когда PHP запрашивает состояние объекта.
```

Вызов конструктора, внедрение свойств и действия `#[SetUp]` откладываются до инициализации. `#[NoConstructor]` отключает только конструктор.

## Ограничения стандартного механизма

Для `ProxyFactory` требуется хотя бы одно нестатическое свойство экземпляра с собственным хранилищем; в том числе подходит унаследованное закрытое свойство. Если таких свойств нет, стандартная реализация выбрасывает `ResolutionException` до создания объекта. Остальные ограничения определяются самим PHP. Пользовательская реализация `ProxyFactoryInterface` может предусматривать другие механизмы.

При использовании виртуального заместителя фабрика должна вернуть подходящий уже инициализированный объект, отличный от самого заместителя. Для атрибута `#[Proxy]` в точке внедрения дополнительно требуется, чтобы возвращённое значение было экземпляром выбранного класса заместителя. Не следует последовательно оборачивать объект несколькими механизмами отложенного создания.

Атрибут `#[Lazy]` или `#[Proxy]` у класса не изменяет результат обычной прикладной фабрики. Используйте создание через отражение, подходящую точку внедрения либо собственную фабрику отложенного создания. Если отложенное создание не требуется, уберите атрибут либо применяйте обычную фабрику или `ClassDefinition` с соответствующими правилами инициализации.

См. [«Атрибуты»](attributes.md) и [описание нативного интерфейса PHP](https://www.php.net/manual/en/reflectionclass.newlazyproxy.php).
