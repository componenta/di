# Ленивые объекты и виртуальные прокси

`Container::makeLazy()` создаёт нативный lazy ghost, а `makeProxy()` — виртуальный прокси. Сервисы, создаваемые через reflection, могут выбирать их через `#[Lazy]` и `#[Proxy]`.

```php
use Componenta\DI\Attribute\Lazy;

#[Lazy]
final class Catalog
{
    private array $items = [];

    public function count(): int { return count($this->items); }
}

$catalog = $container->get(Catalog::class);
$count = $catalog->count(); // Инициализация ленивого экземпляра при обращении.
```

Конструктор, внедрение свойств и `#[SetUp]` исполняются при инициализации по обычным правилам reflection; `#[NoConstructor]` отключает только конструктор.

## Ограничения

Стандартный `ProxyFactory` требует хотя бы одного **нестатического сохраняемого свойства экземпляра**; унаследованное private-свойство подходит. Классы без свойств либо только со статическими/виртуальными свойствами отклоняются до выделения объекта с `ResolutionException`. Другие ограничения определяет PHP.

Виртуальному прокси нужен подходящий уже созданный backing-объект, а не другой ленивый прокси. При `#[Proxy]` в точке внедрения DI также требует, чтобы backing-объект был экземпляром выбранного класса прокси. Не следует оборачивать сервис с `#[Lazy]` или `#[Proxy]` ещё одним прокси.

Фабрика приложения сама управляет созданием результата: атрибуты класса не превращают её продукт в ленивый объект. Используйте reflection-создание с атрибутом, поддерживаемый путь proxy injection или пользовательскую фабрику. Для обычного создания уберите lazy-маркер либо используйте фабрику/`ClassDefinition`.
