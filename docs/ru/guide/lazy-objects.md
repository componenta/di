# Отложенное создание объектов и виртуальные заместители

Контейнер поддерживает два встроенных в PHP способа отложенной инициализации:

- `#[Lazy]` откладывает заполнение состояния самого объекта до момента, когда оно потребуется.
- `#[Proxy]` откладывает создание отдельного основного объекта до обращения к состоянию заместителя. Заместитель и основной объект остаются разными экземплярами.

Оба атрибута применяются к классам, создаваемым средствами отражения PHP. Атрибут `#[Proxy]` также применяется к параметрам и свойствам. Для явного создания предусмотрены методы `makeLazy()` и `makeProxy()` (см. [справочник фабрик](../api/lazy.md)).

## Когда выполняется инициализация

```php
use Componenta\DI\Attribute\Lazy;

#[Lazy]
final class Catalog
{
    public function __construct(private array $items = []) {}

    public function name(): string
    {
        return 'catalog';
    }

    public function count(): int
    {
        return count($this->items);
    }
}

$catalog = $container->get(Catalog::class);
$catalog->name();  // Инициализация не выполняется.
$catalog->count(); // Чтение $items запускает инициализацию.
```

Сам по себе вызов метода не запускает инициализацию. PHP выполняет её при обращении к состоянию объекта, например при чтении свойства. Для объектов, создаваемых средствами отражения, контейнер в этот момент разрешает аргументы конструктора, вызывает конструктор, внедряет свойства и выполняет `#[SetUp]`. Атрибут `#[NoConstructor]` отключает только вызов конструктора.

## Зачем необходимо свойство с хранилищем

Стандартная реализация `ProxyFactory` требует хотя бы одного объявленного нестатического свойства экземпляра, в котором хранится значение. Подходит и унаследованное закрытое свойство. Это связано с тем, что механизм PHP отслеживает отложенную инициализацию через свойства объекта. Если таких свойств нет (например, все свойства статические или виртуальные), методы `ReflectionClass::newLazyGhost()` и `newLazyProxy()` возвращают обычный, а не ленивый экземпляр. При этом конструктор, функция инициализации или фабрика основного объекта не считаются выполненными: PHP не вызывает их при таком создании.

Чтобы контейнер не возвращал объект, пропустивший необходимую инициализацию, `ProxyFactory` заранее выбрасывает `ResolutionException` для таких в остальном допустимых классов. Функция не выполняется немедленно, и переход к обычному созданию не происходит автоматически. Это относится и к самому классу `stdClass`, у которого нет объявленных свойств с хранилищем. Пользовательская реализация `ProxyFactoryInterface` может использовать иной механизм.

Не добавляйте фиктивное свойство только для обхода этого ограничения. Если отложенная инициализация не нужна, уберите атрибут: контейнер создаст объект обычным способом. Можно также использовать явную фабрику или `ClassDefinition`, если необходимо самостоятельно управлять созданием; атрибуты внедрения зависимостей целевого класса в этом случае автоматически не выполняются.

## Ограничения виртуального заместителя

Фабрика, переданная в `makeProxy()`, должна вернуть совместимый объект, который не является ленивым и отличается от самого заместителя. PHP допускает объект того же класса либо, с учётом [ограничений наследования](https://www.php.net/manual/ru/reflectionclass.newlazyproxy.php), подходящего родительского класса. При применении `#[Proxy]` к параметру или свойству контейнер дополнительно требует, чтобы основной объект был экземпляром выбранного класса заместителя.

В точке внедрения основной объект создаётся через `make()` с идентификатором и аргументами из `#[Make]`, если этот атрибут указан. Не оборачивайте уже ленивый объект в ещё один встроенный заместитель. Атрибут класса не превращает результат прикладной фабрики в ленивый объект автоматически; для управления отложенным созданием фабрика может реализовать [LazyServiceFactoryInterface](../api/lazy.md).

См. [«Жизненный цикл и условия инициализации ленивых объектов в PHP»](https://www.php.net/manual/ru/language.oop5.lazy-objects.php) и [справочник атрибутов](attribute-reference.md).
