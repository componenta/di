# Интерфейс контейнера

`Container` реализует `Psr\Container\ContainerInterface`, `FactoryInterface`, `CallableExecutorInterface` и `ProxyFactoryInterface`.

## Получение значений и создание объектов

```php
$shared = $container->get(Service::class);
$known = $container->has(Service::class);
$created = $container->make(Service::class, ['id' => 42]);
```

- `get(string $id): mixed` возвращает общее значение собственной записи контейнера с учётом обработчиков результата. Для значений внешнего контейнера правила повторного использования определяет сам внешний контейнер.
- `has(string $id): bool` проверяет, известна ли запись. Положительный результат не гарантирует успешного разрешения зависимости.
- `make(string $entry, array $params = []): object` создаёт объект по собственному определению либо через запасной способ разрешения. Метод не использует общие значения, внешние контейнеры и обработчики результата. Фабрика может намеренно вернуть ранее созданный объект.

Если явного определения нет, конкретный класс можно создать с помощью механизма отражения PHP и внедрения аргументов конструктора. Явные определения имеют приоритет.

## Вызов функций и методов

```php
$result = $container->call([$controller, 'show'], ['id' => 42]);
$callable = $container->resolve([Controller::class, 'show']);
```

`call(mixed $callable, array $params = []): mixed` разрешает зависимости параметров и вызывает указанную функцию или метод. `resolve(mixed $callable): callable` преобразует описание вызова в вызываемое значение, не выполняя его. Строка вида `Class::method` и массив с именем класса и метода могут использовать `__call()` экземпляра. Параметры таких методов передаются по обычным правилам PHP, без автоматического разрешения зависимостей. Точное совпадение со строковым идентификатором службы имеет приоритет перед разбором записи о методе.

Когда все аргументы уже подготовлены другой цепочкой обработки, `PreparedCallable` позволяет вызвать функцию без повторного внедрения зависимостей. Этот способ не поддерживает ссылочные параметры. Для них следует непосредственно использовать `CallableInvoker` и массив, содержащий необходимые ссылки.

## Параметры переменной длины

При вызове конструкторов через механизм отражения, `call()` и `SetUp` поддерживаются параметры переменной длины:

```php
$join = static fn(string ...$parts): string => implode('-', $parts);

$container->call($join, ['one', 'two']);             // 'one-two'
$container->call($join, ['parts' => ['one', 'two']]); // 'one-two'
$container->call($join);                            // ''
```

Массив под именем параметра переменной длины полностью задаёт его значения и имеет приоритет перед позиционными аргументами, даже если пуст. В остальных случаях используются числовые ключи начиная с позиции этого параметра. Тип каждого элемента проверяется отдельно. Посторонние именованные ключи в набор не добавляются. Строковые ключи внутри явно переданного массива сохраняются как именованные аргументы переменной длины; позиционные элементы должны предшествовать именованным, а именованные не могут заменять предшествующие параметры. При отсутствии значений используется пустой набор. Автоматический поиск зависимостей для отдельных элементов не выполняется. Внедрение через ссылочные параметры не поддерживается.

Необязательные аргументы встроенных функций PHP могут оставаться пропущенными, а не заменяться явным `null`, если применимы стандартные значения.

## Изменение конфигурации при выполнении

```php
$container->set('feature.enabled', false);
$container->alias(CacheInterface::class, RedisCache::class);
$container->delegator(Service::class, static fn($service) => $service);
$container->addContainer($externalPsrContainer);
```

Методы `set()`, `alias()` и `delegator()` изменяют собственные привязки контейнера и сбрасывают затронутые общие значения без повторного построения контейнера. `addContainer()` добавляет внешний контейнер PSR-11; защищённые записи ядра переопределять нельзя.

Когда ранее добавленный внешний контейнер изменил свои записи, об этом можно сообщить через `notifyExternalEntriesChanged($provider, ...$ids)`. Метод обновляет сведения о внешних записях и затронутые цепочки обработчиков результата. Внешний контейнер должен предварительно применить собственные изменения.

Если привязка изменилась во время уже начатого разрешения, текущий вызов может вернуть старое значение. Последующие обращения используют новую привязку; завершение старого вызова не восстанавливает сброшенные значения.

Ошибки и правила повторного использования значений описаны в разделе [«Поведение и исключения»](runtime.md).
