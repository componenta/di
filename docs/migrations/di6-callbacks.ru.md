# Миграция на DI 6: callback-функции и autowiring union-типов

[English version](di6-callbacks.md)

Этот документ описывает реализацию в ветке разработки DI 6 после базового релиза DI 5.0.6. Это не объявление о выпуске DI 6. Код библиотеки по-прежнему разбирается PHP 8.4; встроенные callback-функции и ссылки first-class callable непосредственно в аргументах атрибутов требуют PHP 8.5.

**Минимальная поддерживаемая patch-версия PHP ещё не определена.** Условие E1 в [спецификации callback-функций](../plans/php85-callbacks.ru.md#8-версия-php-и-совместимость-релиза) блокирует соответствующее обещание поддержки платформы и окончательную подготовку релиза DI 6. В PHP 8.5.8 воспроизведён дефект движка для first-class ссылок, зависящих от области видимости трейта. Ветка не повышает требование Composer, не объявляет поддержку всех patch-версий PHP 8.5 и не эмулирует лексическую область видимости PHP. Подробнее — в разделе [ограничений платформы](#8-ограничения-платформы).

## 1. Что проверить перед обновлением

| Область | Поведение DI 6 | Действие при миграции |
| --- | --- | --- |
| `Transform` | Новый повторяемый атрибут параметра/свойства, принимающий одну `Closure`. | Выбрать явный источник значения, проверить первый параметр callback-функции и последующие DI-параметры. |
| `SetUp::$method` | Тип расширен с `string` до `string\|Closure`; имена и порядок аргументов конструктора остаются `method`, `params`. | Удалить или расширить повторное объявление `string $method` в подклассе. Проверить прямое создание `SetUpRunner`. |
| Setup через метод | Строка по-прежнему означает имя публичного, конкретного, нестатического метода экземпляра. | Существующие `#[SetUp('initialize')]` и именованные аргументы сохраняют смысл. |
| `Init` | Существующий API `Init(mixed $callable, array $params = [])` сохранён. | Строки, массивы и invokable-объекты остаются допустимыми. Новый синтаксис необязателен. |
| Autowiring простого union-типа | Выбирается единственная доступная ветвь класса/интерфейса; несколько доступных ветвей вызывают ошибку. | Проверить union-параметры, ранее получавшие default/null, и неоднозначные регистрации сервисов. |

Изменения callback-функций и union-типов независимы. Существующий `Init` уже может использовать нативные выражения PHP 8.5 в линейке 5.x; новый `Transform`, callback-вариант `SetUp` и выбор union-кандидата относятся к этой ветке разработки.

## 2. Используйте поддерживаемые нативные выражения

Допустимы статические замыкания без захватов и first-class ссылки на именованные функции и объявленные статические методы:

```php
use Componenta\DI\Attribute\Transform;

final class EmailInput
{
    public function __construct(
        #[Transform(trim(...))]
        #[Transform(static function (string $value): string {
            return strtolower($value);
        })]
        public string $email,
    ) {}
}

$input = $container->make(EmailInput::class, ['email' => ' Alice@Example.COM ']);
// $input->email === 'alice@example.com'
```

Эти выражения требуют PHP 8.5. `static fn`, нестатические литералы замыканий, захваты через `use (...)`, динамические выражения вроде `[Formatter::class, 'normalize'](...)` и ссылки на методы объектов недопустимы в аргументах таких атрибутов. Ссылка, разрешаемая только через `__callStatic()`, может пройти разбор, но завершится ошибкой при создании экземпляра атрибута движком PHP. Одной синтаксической проверки для этого случая недостаточно.

Ограничения относятся к нативному синтаксису константных выражений. Они не отменяют runtime-вызовы через строки, массивы и invokable-объекты в `Init` и обычных вызовах контейнера. DI отражает и вызывает исходную `Closure`, не перепривязывая её, не извлекая исходный текст и не восстанавливая область видимости. Допустимая ссылка на private static-метод сохраняет свой нативный лексический доступ.

## 3. `Transform`: источник, порядок и результат

Публичный API:

```php
#[Attribute(Attribute::TARGET_PARAMETER | Attribute::TARGET_PROPERTY | Attribute::IS_REPEATABLE)]
final readonly class Transform
{
    public function __construct(public Closure $callback) {}
}
```

Аргументов `params`, `default`, ID сервиса или mapper нет. Преобразователь выполняется после поставщиков значения; несколько преобразований идут в порядке объявления. `Cast` и `Transform` сохраняют взаимный порядок объявления, если явно зарегистрированное правило композиции не меняет его.

Для параметра callback-функция получает текущее значение из явного аргумента, поставщика или предыдущего преобразователя, включая `null`. Если значения ещё нет, неразрешённый variadic-параметр получает один пустой массив; иначе используется объявленное значение по умолчанию для этой попытки, затем `null` для nullable-параметра. Обязательный параметр без такого источника вызывает ошибку до выполнения тела callback-функции. Переданное некорректное значение не приводит к переходу на default.

`Transform` не выполняет неявный autowiring самого преобразуемого параметра. Для нового объекта используйте `#[Make(Service::class)]`, для shared-сервиса — `#[EntryId('service.id')]`. Дополнительные параметры callback-функции могут получать зависимости через autowiring.

Для свойства нужен поставщик либо явный ключ контекста создания, совпадающий с именем свойства. Объявленный default изменяемого свойства не является источником для самостоятельного преобразователя. Например:

```php
use Componenta\DI\Attribute\Init;
use Componenta\DI\Attribute\Transform;

final class Label
{
    #[Init(static function (): string { return ' ready '; })]
    #[Transform(trim(...))]
    public readonly string $value;
}
```

Преобразования свойства работают с отложенными значениями. Существующий object pipeline записывает финальное значение один раз, сохраняя инициализацию readonly и поведение setter-hook. Setter может принимать более широкий тип, чем читаемый тип свойства; за такое преобразование отвечает нативное присваивание. Инициализированные readonly- и promoted-свойства сохраняют прежние правила пропуска; static- и get-only virtual-свойства по-прежнему недопустимы для injection.

Результат преобразователя, включая `null` или фактический результат callback-функции с `void`, становится следующим значением. Финальная проверка параметра проверяет весь объявленный тип. Variadic-цель передаёт всю коллекцию callback-функции один раз, затем финальная коллекция проверяется и раскрывается по существующим правилам порядка нативных аргументов.

## 4. Первый параметр зарезервирован для смыслового значения

Оба вида callback-функций используют единый контракт связывания аргументов:

| Callback-функция | Первый объявленный параметр | Остальные параметры |
| --- | --- | --- |
| `Transform` | Текущее значение; массив целиком передаётся одним аргументом. | Разрешаются обычной DI-цепочкой с пустым публичным набором переданных параметров. |
| Callback `SetUp` | Созданный объект. | Разрешаются обычной DI-цепочкой с описанным ниже setup-контекстом. |

Первый параметр может иметь любое имя, быть nullable или optional. Его default не заменяет смысловое значение. Объявленный тип должен принимать это значение по существующим строгим правилам DI. By-reference и variadic для первого параметра недопустимы. By-reference для последующих параметров также остаётся неподдерживаемым.

Первый параметр не проходит ни классификацию, ни выполнение пользовательских resolver-ов. Зарегистрированные DI-атрибуты на нём, включая зарегистрированные атрибуты только с метаданными, недопустимы; обычные метаданные вроде `SensitiveParameter` разрешены. Позднее обнаружение запрещённых метаданных первого параметра либо изменения уже завершённой части DI-параметров вызывает ошибку до тела callback-функции без повторного выполнения завершённых handler-ов.

Последующие параметры сохраняют исходные позиции и обычное поведение resolver-ов: атрибуты-поставщики, пользовательские resolver-ы, разрешённые переданные значения, autowiring, defaults, nullable fallback, пропуск внутренних нативных defaults и variadic. Пользовательский resolver такого параметра видит реальное смысловое значение в `ParameterResolutionContext::$resolved[0]`.

Callback-функция без параметров получает ноль нативных аргументов. Для преобразователя без параметров всё равно нужен допустимый источник входного значения. Во всех случаях выполняется один вызов через `PreparedCallable` и существующий callable invoker; второго DI-прохода по зарезервированному параметру нет.

`Transform` не наследует внешний набор аргументов конструктора, DTO или запроса. Внешнее поле с именем дополнительного параметра не может заменить его зависимость; текущий HTTP-запрос не передаётся неявно. Нужные сервисы разрешаются собственными DI-правилами дополнительных параметров.

## 5. Callback-вариант `SetUp`

Атрибут остаётся readonly, non-final и повторяемым:

```php
public function __construct(
    public string|Closure $method,
    public array $params = [],
) {}
```

Именованный аргумент конструктора `method:` сохранён для обоих вариантов. Строки по-прежнему обозначают методы экземпляра, а не имена глобальных функций или ID сервисов. Для именованной функции или объявленного static helper используйте first-class ссылку в виде `Closure`.

```php
use Componenta\DI\Attribute\Inject;
use Componenta\DI\Attribute\SetUp;

final class Formatter
{
    public function format(string $value): string { return strtoupper($value); }
}

#[SetUp(
    method: static function (Worker $instance, Formatter $formatter, string $label = 'ready'): void {
        $instance->label = $formatter->format($label);
    },
    params: ['label' => 'started'],
)]
final class Worker
{
    #[Inject]
    public readonly Formatter $formatter;

    public string $label;
}
```

Callback-функция выполняется после завершённой записи внедрённых свойств. Повторяемые hooks через методы и callback-функции сохраняют порядок объявления. Возвращаемое значение игнорируется, включая возвращённый объект: setup не может заменить созданный экземпляр. Shared `get()` по-прежнему инициализирует один раз, `make()` создаёт независимые экземпляры, а lazy-объекты откладывают setup до инициализации.

### Переданные setup-параметры

Callback-ветвь проверяет явные `params` до запуска любого value unwrapper:

- Каждый явный ключ должен быть строкой. Любой целочисленный ключ, включая `0`, отклоняется с `InvalidConfigurationException`.
- Имя первого параметра зарезервировано и не может присутствовать в явных `params`.
- Позиция `0` и имя первого параметра удаляются из окружающего набора для связывания. Позиции `1` и выше сохраняются без перенумерации.
- Совпадающее имя дополнительного параметра разворачивается с его реальным `ReflectionParameter`. Остальные строковые ключи, включая неиспользуемые имена и ключи типов классов, остаются допустимыми и разворачиваются с `null` вместо reflection-метаданных.
- Явные публичные значения перекрывают окружающие публичные значения. Закрытые DI-метаданные сохраняются отдельно; их нельзя перезаписать или раскрыть пользовательским resolver-ам параметров.

Неиспользуемые ключи не превращаются в дополнительные нативные аргументы. У callback-функции без параметров нет зарезервированного имени, но она всё равно отклоняет целочисленные ключи и разворачивает именованные значения до пустого нативного вызова. Эти ограничения относятся к callback-ветви; прежнее связывание параметров setup через метод не меняется.

Сведения о происхождении mapped request-данных сохраняются при переходе в setup. Сырые ключи запроса не могут перекрыть явный источник дополнительного параметра вроде `EntryId` или `Env`, совпадая с именем параметра или ключом типа. Это распространяется на callback-функции без declaring class и источники, загруженные во время разрешения другой зависимости. Диагностика указывает создаваемый DTO; ни provenance, ни этот диагностический владелец не добавляются в публичный контекст расширений.

### Миграция подклассов

Типы свойств PHP инвариантны. Подкласс с повторным объявлением `public string $method` становится недопустимым, когда тип родительского свойства — `string|Closure`. Удалите избыточное объявление свойства либо укажите точно такой же тип `string|Closure`, если повторное объявление необходимо. Конструктор, который лишь передаёт строку родителю, остаётся допустимым:

```php
use Componenta\DI\Attribute\SetUp;

#[Attribute(Attribute::TARGET_CLASS)]
readonly class ProjectSetUp extends SetUp
{
    /** @param array<string, mixed> $params */
    public function __construct(string $method, array $params = [])
    {
        parent::__construct(method: $method, params: $params);
    }
}
```

Потребителям, напрямую создающим инфраструктуру, также нужно обновить создание `SetUpRunner`. Его обязательный третий аргумент — общий helper перед прежними variadic unwrappers:

```php
$callbacks = new Componenta\DI\Internal\AttributeCallbackInvoker($parameters, $invoker);
$runner = new Componenta\DI\Resolver\Entry\SetUpRunner(
    $invoker,
    $resolutionParameters,
    $callbacks,
    ...$valueUnwrappers,
);
```

Здесь `$parameters` — `ParametersResolver`, `$invoker` — `CallableInvokerInterface`, а `$resolutionParameters` — `ObjectResolutionParameterStore`. Стандартная фабрика создаёт один helper для setup и преобразований; приложениям с обычной фабрикой ручное связывание не требуется. Helper остаётся внутренним и не получает новой публичной регистрации сервиса. `SetUpRunner::providedParameters()` теперь принимает `?ReflectionFunctionAbstract` под прежним именем аргумента `method`, чтобы unwrappers получали метаданные дополнительных параметров как методов, так и функций.

## 6. Autowiring union-типов меняет выбор зависимости

Неявный выбор поддерживает не-variadic простые union-типы с именованными ветвями. Встроенные типы не создают сервисных кандидатов. ID классов/интерфейсов дедуплицируются без учёта регистра и проверяются в стабильном порядке через существующий контракт `has()` контейнера. Intersections и DNF-union с intersection-ветвями остаются вне неявного поиска; явно переданные значения всё равно проходят полную проверку типа.

| Доступные ID кандидатов | Результат |
| --- | --- |
| Ни одного | Оставить параметр неразрешённым; применяются существующие правила вызывающего пути для default/null/пропуска. |
| Ровно один | Один раз вызвать `get()` и потребовать соответствия результата выбранному сервисному типу и полному типу параметра. |
| Больше одного | Выбросить `ResolutionException` со стабильным отсортированным списком кандидатов до создания любого из них. |

Два ID интерфейсов, являющихся alias одного implementation, всё равно считаются двумя кандидатами. DI не создаёт их для сравнения идентичности. Устраняйте неоднозначность явным значением или поставщиком, например `#[EntryId('primary.clock')] ClockA|ClockB $clock`.

Особенно внимательно проверьте nullable/defaulted union-параметры: одна новая доступная ветвь теперь выбирается до fallback на default или null. Default не устраняет неоднозначность. После начала создания выбранного кандидата его ошибка распространяется наружу; DI не выбирает молча другую ветвь и не возвращается к null. `has()` может запускать autoload и не гарантирует успешного создания.

Явная регистрация `Closure::class` участвует на общих основаниях. Выбранная регистрация `Service::class`, возвращающая замыкание, недопустима даже при полном типе параметра `Closure|Service`: соответствие другой ветви не выполняет контракт выбранного ID. Доступность кандидатов пересчитывается при каждом разрешении, поэтому прогретые планы замечают изменения сервисов, alias и владения во внешнем контейнере.

Явно включённый autowiring конструктора и настроенных публичных методов `ClassDefinition` использует тот же алгоритм выбора. Существующие lifecycle- и fallback-контракты этого пути остаются отдельными: обработка новых атрибутов и неявная setup-фаза не добавляются, неразрешённый аргумент пропускается. Тогда объявленный default может примениться нативно; обязательный nullable-параметр без default по-прежнему означает отсутствующий аргумент. Обычное reflection-создание и DI-aware вызовы сохраняют прежний nullable fallback.

## 7. Исключения, повторные попытки и время жизни

Некорректное объявление зарезервированного параметра или явные setup-ключи вызывают `InvalidConfigurationException`; несовместимые поздние метаданные — существующее `AttributeCompositionException`. Неверный тип первого значения либо неразрешённый/некорректный дополнительный параметр используют диагностику разрешения параметров. Внешние исключения внутри преобразований или setup проходят через существующую границу владельца параметра/свойства/объекта как `ResolutionException` с исходной причиной. Исключения тела цели обычного прямого `container->call()` по-прежнему распространяются без изменения.

Неудачное преобразование свойства не записывает его отложенное значение. Неудачный setup не публикует объект как успешно созданный shared-сервис. Эти границы не откатывают внешние побочные эффекты и записи ранее обработанных свойств. Lazy-инициализация может повторяться по существующим lifecycle-правилам; завершённая работа не выполняется повторно в той же попытке для исправления конфликта метаданных.

Нативное состояние сохраняется. У заново материализованного встроенного статического замыкания свежие локальные static-переменные. First-class wrappers именованных функций/static-методов разделяют static-состояние исходной функции. Замыкание в константе остаётся общим, поскольку им владеет константа. DI не кеширует runtime-экземпляры callback-функций, значения или результаты, чтобы изменить эти правила. Контрактные fixtures проверяют повторное создание, lazy-повторы и освобождение иначе недостижимых callback-функций, смысловых объектов и объектов в локальных static-переменных встроенных замыканий.

`Init` по-прежнему получает значение свойства из обычного DI-aware callable. Он **не** получает владельца свойства неявным первым аргументом. Сохранены прежние формы callable, явные параметры, readonly-инициализация и lazy-поведение.

## 8. Ограничения платформы

Проверенный движок PHP 8.5.8 ошибочно повторно использует область видимости первого потребителя трейта для некоторых first-class ссылок атрибутов через `self::` или `parent::`; именованная private-ссылка также может сохранять результат проверки видимости для первого потребителя. Нативный контроль со встроенным статическим замыканием правильно различает потребителей. Дефект воспроизводится без DI.

E1 остаётся открытым, пока выпущенная patch-версия PHP не пройдёт fixtures правильной области видимости и доступа для каждого потребителя и не установит поддерживаемый минимум. DI не перепривязывает callback-функции для сокрытия дефекта. Статические замыкания без захватов и полностью квалифицированные ссылки на публичные helper-функции входят в проверенные альтернативы; их успех не означает поддержку всех затронутых trait-relative выражений.

Тесты совместимости ветки с PHP 8.4 покрывают реализацию библиотеки и замыкания, созданные в runtime. Подпроцессы PHP 8.5 проверяют новый синтаксис атрибутов и ошибки материализации. Эти результаты не равнозначны окончательному объявлению поддержки платформы.
