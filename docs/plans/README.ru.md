# Архитектурные планы

[English version](README.md)

Планы перепроверены 13 ноября 2026 года по навыку implementation-specification: в каждом отделены целевой контракт, выведенные из него шаги реализации, критерии приёмки и оставшиеся условия готовности. Готовность к реализации описывает контракт для написания кода, а не разрешение на реализацию или выпуск. Опубликованный релиз v5.0.5 сохраняет существующий API и требование PHP `^8.4`.

| План | Английская спецификация | Полный русский перевод | Готовность и выбранное направление |
| --- | --- | --- | --- |
| Владение определениями и освобождение объектов при мутациях | [English](definition-owner-lifecycle.md) | [Русский](definition-owner-lifecycle.ru.md) | Готово к реализации в следующей major-версии: одна таблица неизменяемых регистраций в `CompositeResolver`, стратегии выполнения без карт регистраций и внутренний барьер `MutationRetirement`. Меняется публичный протокол расширения резолверов определений; это не исправление для 5.x. |
| Проверка доступности атрибутов | [English](attribute-availability-performance.md) | [Русский](attribute-availability-performance.ru.md) | G1 решён для текущей 5.x: сохранить исправленный опрос; широкая оптимизация не выбрана. B2 — предпочтительное условное направление, если затраты приложения оправдают пересмотр контракта синхронизации и доказательства G2/G3. C не выбран; A не принят. |
| Callbacks PHP 8.5 и autowiring union-типов | [English](php85-callbacks.md) | [Русский](php85-callbacks.ru.md) | Примеры и регрессионные проверки существующего `Init` — совместимая работа. Контракты связывания callback, `Transform`, callback-формы `SetUp` и простых union-типов готовы к написанию кода в будущей major-ветке. E1 блокирует обещание нативной поддержки callable из trait и выбор окончательного минимального patch-релиза PHP для выпуска DI 6, при этом указанные участки библиотеки можно реализовывать и проверять. Callbacks преобразования запроса в DTO остаются отдельно заблокированными. |

Русские документы полностью переводят спецификации и планы реализации: контракты, примеры, критерии приёмки и блокирующие решения. Символы кода и идентификаторы проверок совпадают с английскими версиями. При изменении контракта нужно обновлять обе версии.

В [повторной проверке всей библиотеки и спецификаций](../audit/2026-11-13-full-library-recheck.ru.md) и её [машиночитаемых доказательствах](../audit/2026-11-13-full-library-evidence.json) описаны последующие исправления в main, измерения нагрузки, границы исходников и оставшиеся ограничения жизненного цикла. Этот отчёт сохраняет предыдущий аудит как историческое доказательство и не объявляет ещё один релиз.
