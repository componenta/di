## Architecture decisions

| Area | Recheck and decision criteria |
|---|---|
| **P1 · Publication after bootstrap** | A destructor declares an attribute during proof cleanup on both runtimes. Container creation succeeds, its shared object holds `null` and fresh creation injects `stdClass`. Define publication and post-cleanup failure ownership while preserving shared identity and a single execution of application effects. [Plan](bootstrap-finalization-boundaries.md) |
| **P2 · External PSR-11 ownership** | Relinquishing one ID during `has()` of another leaves a shared decorator result from its previous owner. Stable ownership and the release-on-second-probe control pass. Precise invalidation requires observable ownership changes or an explicit provider stability guarantee. [Plan](external-provider-ownership.md) |
| **P2 · Lifetime of a binding hidden by a runtime alias** | A previously accessible value and factory remain alive after `alias()` until the container is released. Destructor timing, in-flight resolution and nested mutations affect the cleanup contract. [Witness](#lifetime-of-a-binding-hidden-by-an-alias) |
| Hidden autoloader readiness | The registry witness declares the skipped name on the second poll after a private readiness change. A stronger guarantee depends on how readiness is communicated. The stale bootstrap object above has a separate cause. [Plan](bootstrap-finalization-boundaries.md) |
| Static return types | PHPStan accepts a consumer returning `Expected` from `make(Expected::class)` while a permitted definition produces `Actual` and the consumer gets a native `TypeError` on both runtimes. Any PHPDoc or typed API decision requires a consumer review. Permissive ID bindings are a compatibility criterion. [Plan](standalone-api-surface.md) |
| Standalone APIs | Existing contracts exercise separately constructed strategies and object creation. Preparation, support and callback-timing guarantees need a policy for external consumers. [Plan](standalone-api-surface.md) |
| Relative callable values | Validation of deprecated `self` and `static` callable values depends on receiving context. The native comparison and explicit routes were reproduced. Native PHP 8.5 callback expressions were checked independently. [Plan](relative-callable-context.md) |
| Instance-callable string owner | A class alias containing `::` can collide with a qualified ancestor route. Both explicit routes and current string precedence were reproduced. A stronger contract must align ownership, discovery and delegator dependency invalidation. [Plan](relative-callable-context.md) |
| Late-loaded static delegators | For ordinary and separator-bearing aliases, the conservative dependency recorded before loading triggers a second invocation after mutation. Precise dependency cleanup requires coordinated publication of the cached result and dependency index. [Plan](relative-callable-context.md) |
| Configuration normalization | A failing direct `assertShape(&$sections)` has already canonicalized `invokables` and published an alias to the caller's array. Both runtimes reproduce it. Atomic failure and stronger reference typing require a contract. [Plan](configuration-normalization-contract.md) |
| Large alias graphs | Terminal-first chains retain quadratic cold validation. Revisit the algorithm when application startup measurements justify it and preserve diagnostic order, cycle paths and mutation semantics. [Plan](large-alias-graphs.md) |
| Shared native lazy objects and Fibers | Native and DI ghosts expose intermediate `starting`. Native and DI proxies have the same uninitialized-property error while suspended. Initialization synchronization requires its own contract. [Plan](native-lazy-fiber.md) |
| Attribute availability polling | Repeated missing-name checks have a measurable cost. Changing their frequency depends on an agreed notification model and measured application cost. [Plan](attribute-availability-performance.md) |

### Lifetime of a binding hidden by an alias

`alias()` rewrites routing and invalidates requested-ID results. The old canonical slot can still hold its base value and definition. Public alias registration has no removal operation. Both PHP versions returned the new route, retained the old factory and product even after garbage collection, and released them when the container was collected. The effect in a long-running container depends on the number and size of the hidden registrations. The ownership decision must account for destructor timing and failure, in-flight work and reentrant publication. Acceptance must preserve alias registration over existing IDs, in-flight results and the identity of unaffected services. [Alias implementation](../../src/Container.php) · [Ownership contract](definition-owner-lifecycle.md)

Save this witness outside the checkout and run `php /path/to/witness.php` from the repository root with the development dependencies installed.

```php
<?php

declare(strict_types=1);

use Componenta\DI\Tests\Support\ContainerBuilder;

require getcwd() . '/tests/bootstrap.php';

function observe(bool $definition): array
{
    $builder = new ContainerBuilder();
    $owner = $definition ? new class {
        public function __invoke(): stdClass
        {
            return new stdClass();
        }
    } : new stdClass();
    $replacement = new stdClass();
    if ($definition) {
        $builder->addFactory('previous', $owner);
    } else {
        $builder->addService('previous', $owner);
    }
    $container = $builder->addService('replacement', $replacement)->build();
    $product = $container->get('previous');
    $ownerRef = WeakReference::create($owner);
    $productRef = WeakReference::create($product);
    unset($owner, $product, $builder);

    $container->alias('previous', 'replacement');
    gc_collect_cycles();
    $during = [
        'new_route' => $container->get('previous') === $replacement,
        'old_owner_live' => $ownerRef->get() !== null,
        'old_product_live' => $productRef->get() !== null,
    ];
    unset($container);
    gc_collect_cycles();

    return $during + [
        'old_owner_released_with_container' => $ownerRef->get() === null,
        'old_product_released_with_container' => $productRef->get() === null,
    ];
}

echo json_encode(['value' => observe(false), 'factory' => observe(true)], JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR), PHP_EOL;
```

## Security and stability

- The first local pass followed PSR-7 data through source merging, transformations, `afterMap`, argument binding and late attribute discovery. The provenance checks cover the affected parameter bag. Extension contexts expose public parameters. Applications choose DTO types, trusted callbacks and validation implementations. [Request handler](../../src/Resolver/Attribute/Handler/RequestAttributeHandler.php) · [Source guard](../../src/Internal/Resolver/Parameter/Request/MappedRequestParameterSourceGuard.php)
- A second pass checked configuration and PSR-11 dispatch, protected IDs, cache mutation publication, diagnostics and the release dependency chain. The production source contains no `eval`, deserialization, external process spawning, file writes or network requests. DI stores detached diagnostic names and types. Previous exceptions and runtime traces can carry extension-owned data. [Container](../../src/Container.php) · [Diagnostics](../../src/Exception/ResolutionException.php) · [Release workflow](../../.github/workflows/release.yml)
- The default native adapter's rejection of propertyless lazy classes matches its lifecycle contract. Initialization failures remain retryable. Magic methods receive native arguments where there is no selected concrete signature for DI to bind. [Lazy contract](propertyless-lazy-lifecycle.md) · [Magic dispatch controls](../../tests/Contract/MagicCallableSyntaxContractTest.php)
- The examined HTTP-to-invocation and DTO paths yielded no confirmed vulnerability. `composer audit` reported zero advisories and abandoned packages for the installed development graph and the lowest production graph. Automated Codex Security Deep Scan was unavailable in this environment. [Manifest](../../composer.json)

## Performance and verification

Benchmarks ran on Linux x86-64 with PHP 8.4.28 and CLI OPcache disabled. The baseline and patch used the same Composer dependencies.
Five existing benchmarks ran in four separate processes in baseline, patch, patch, baseline order. Each run verified its source paths. The table shows the range of two medians for each version. [Benchmark harnesses](../../benchmarks)

| Case | Baseline | Patch |
|---|---:|---:|
| Warm `get()` | 102.1–104.2 ns | 103.1–106.2 ns |
| Autowired `make()` | 8.78–8.83 µs | 8.63–9.53 µs |

The measured hot-path ranges overlap. These synthetic workloads and variability in controls limit claims about real applications. Missing-attribute counts were stable. [Polling benchmark](../../benchmarks/AttributeAvailabilityBench.php)

## Architecture fixes

- Bootstrap checks newly loaded DI declarations on consumed targets after releasing temporary references. A suspended resolver checks its consumed prefix even after the container factory returns. [Bootstrap cleanup](../../tests/Contract/BootstrapProofRetirementContractTest.php) · [Fiber](../../tests/Contract/BootstrapInFlightFinalizationContractTest.php)
- Consumed constructor parameter metadata stays with the current attempt until completion. An incompatible policy fails creation or initialization before successful publication. [Constructor test](../../tests/Contract/CompletedConstructorArgumentsContractTest.php)
- `get()` uses PSR-11 NotFound for an absent requested route and `ResolutionException` with the original cause for a missing dependency. [PSR-11 test](../../tests/Contract/PsrLookupFailureContractTest.php)
- Cached delegator routes and their dependency index share a revision. `notifyExternalEntriesChanged()` refreshes the affected chains, including changes reported during another provider's registration. [Late static route](../../tests/Contract/StaticDelegatorInvalidationContractTest.php) · [External update](../../tests/Contract/ExternalOwnershipNotificationContractTest.php)
- `alias()` releases unreachable definitions and base values after publishing the route. The base revision prevents an in-flight result from restoring those entries. [Retirement](../../tests/Contract/MutationRetirementContractTest.php) · [In-flight resolution](../../tests/Contract/EntryCachePublicationContractTest.php)
- The annotations for `get()` and `make()` reflect the values supported by opaque service IDs, including class names. [Result typing](../../tests/Contract/TypedEntryContractTest.php)
- Alias graph validation reuses terminal IDs as edges are appended. Normalization passes the validated graph to container construction. [Normalization order](../../tests/Contract/DependencyNormalizationContractTest.php) · [Cycle diagnostics](../../tests/Contract/AliasConfigurationContractTest.php)
- The targeted discovery factory confines optional-loader failures to their declarations. The default factory preserves its observable autoload order. [Targeted discovery](../../tests/Contract/TargetedAttributeDiscoveryContractTest.php)

The [migration guide](../migrations/di6-definitions.md#entry-resolution-and-metadata-updates) covers exception types, retirement timing and entry result types.

### Performance after the fixes

The baseline contains the preceding audit fixes on top of `9fb0750`. The runs used PHP 8.4.28 and 8.5.13 with CLI `-n`, JIT disabled and one Composer dependency installation. Processes were pinned to the same core within each series and baseline and candidate order alternated. Each process reported the median of seven rounds. Percentage deltas below are medians of paired process differences. A positive percentage means higher latency.

| Workload | PHP 8.4.28 | PHP 8.5.13 |
|---|---:|---:|
| Default container construction | −0.2% | +2.1% |
| Warm `get()` | +1.1% | −0.4% |
| Argumentless `make()` | +2.6% | +3.0% |
| Autowired `make()` | +2.7% | +1.8% |
| Method-array `call()` | +0.7% | −0.2% |
| `call()` with a reused closure | **+5.1%** | **+3.3%** |
| DTO mapping with a callback | +1.7% | −0.6% |
| Explicit-factory `make()` | −4.0% | −0.2% |
| Exact-ID delegator rebuild through `set()` and `get()` | +3.5% | +4.9% |
| Late native delegator rebuild | +1.7% | +2.4% |

The reused-closure case increased in all four pairs on both PHP versions. The absolute median difference was 0.49 µs on PHP 8.4 and 0.36 µs on PHP 8.5. Warm `get()` ranges overlapped. The PHP 8.4 explicit-factory series had a wide range and does not establish a repeatable improvement.

Shared lookups use an explicit result for a missing route. This restored the direct `make()` path and removed the observed explicit-factory penalty. Delegator resolution captures the route when an owner is provisional. A confirmed native route for a single delegator keeps its precise index across rebuilds. The first implementation increased exact-ID rebuild latency by 23–26%. The final comparison measured 3–5%, with overlapping ranges on both versions. [Runtime benchmark](../../benchmarks/RuntimeBench.php) · [Factories](../../benchmarks/GeneratedVsReflectionBench.php) · [Delegators](../../benchmarks/DelegatorInvalidationBench.php)

|---|---:|---:|
| Terminal-first chain of 2,400 aliases | 463.6 → 0.98 ms | 470.7 → 1.31 ms |
| 2,400 matching explicit aliases and invokable keys | 979.8 → 1.32 ms | 1,092.1 → 1.87 ms |

One and eight unavailable attributes still produce 24 and 192 autoloader calls per `make()` in the default mode. The optimization allocates the additional tracking array only when reentrant discovery adds names. In targeted mode, both cases make zero calls for unrelated declarations. [Alias graph benchmark](../../benchmarks/AliasGraphBench.php) · [Attribute availability](../../benchmarks/AttributeAvailabilityBench.php)

Runtime, factory and delegator rebuild comparisons used four process pairs per PHP version. Graphs and the final discovery verification used two pairs. The graph measurement times `ContainerFactory::create()` before checking the resolved aliases. Delegator samples execute `set()` and `get()` for each iteration. The graph and delegator snapshots preceded final optimizations in branches those workloads do not execute. The remaining rows were remeasured from the final tree. These synthetic results describe the workloads shown above.

To reproduce the runs, set `COMPONENTA_DI_BENCH_SOURCE` to the selected `src` snapshot and use the same Composer installation in `COMPONENTA_DI_BENCH_AUTOLOAD` for each comparison. Set `DI_BENCH_TARGETED_DISCOVERY=1` for the targeted series. The runners verify the origin of loaded classes.

PHPStan and PHP CS Fixer passed on the final tree. Pest passed 2,633 tests on PHP 8.4.28 and 2,652 tests on PHP 8.5.13. The separate production consumer installation passed its smoke test on both versions with the lowest dependency graph.
