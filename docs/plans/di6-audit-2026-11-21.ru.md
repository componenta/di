## Архитектурные решения

| Тема | Результат проверки и критерий для решения |
|---|---|
| **P1 · Публикация после bootstrap** | На обеих PHP деструктор при очистке записей проверки объявляет атрибут. Фабрика контейнера завершается успешно, общий объект содержит `null`, свежий получает `stdClass`. Требуется определить границу публикации и политику ошибки после очистки с сохранением идентичности общего объекта и однократного выполнения пользовательского кода. [План](bootstrap-finalization-boundaries.ru.md) |
| **P2 · Владение внешнего PSR-11 провайдера** | На обеих PHP смена владельца одного ID из `has()` другого оставляет результат делегатора от прежнего владельца. Контроли со стабильным владельцем и с изменением на втором опросе проходят. Условие для точной инвалидации — наблюдаемое изменение владения либо явно оговорённая стабильность провайдера. [План](external-provider-ownership.ru.md) |
| **P2 · Срок жизни привязки, скрытой runtime-алиасом** | Ранее доступные значение и фабрика остаются жить до освобождения контейнера после `alias()`. Для политики освобождения важны деструкторы, активные разрешения и вложенные мутации. [Воспроизведение](#срок-жизни-привязки-скрытой-алиасом) |
| Скрытая готовность загрузчика | Пример с реестром показывает объявление имени лишь на втором опросе после изменения приватного состояния загрузчика. Дополнительная гарантия зависит от способа сообщать о готовности. Устаревший bootstrap-объект в первом сценарии имеет отдельную причину. [План](bootstrap-finalization-boundaries.ru.md) |
| Статические типы результата | PHPStan принимает wrapper с возвращаемым `Expected`, хотя разрешённая привязка даёт `Actual` и wrapper получает нативный `TypeError` на обеих PHP. Уточнение PHPDoc или отдельный типизированный контракт требуют проверки потребителей. Свободная привязка ID остаётся критерием совместимости. [План](standalone-api-surface.ru.md) |
| Автономные API | Отдельно собранные стратегии и pipeline работают в проверенных контрактных сценариях. Обещания о подготовке, поддержке и моменте исполнения callbacks требуют явной политики для внешних расширений. [План](standalone-api-surface.ru.md) |
| Относительные callable-значения | Для проверки устаревших форм `self` и `static` нужен контекст получателя. Воспроизведены расхождение с нативным вызовом и рабочие явные формы. Нативные callback-выражения PHP 8.5 проверены отдельно. [План](relative-callable-context.ru.md) |
| Владелец строкового instance-callable | Alias класса с `::` может совпасть с маршрутом к методу предка. Воспроизведены оба явных маршрута и приоритет строковой формы. Для уточнения контракта нужно согласовать выбор владельца, автозагрузку и индекс зависимостей делегаторов. [План](relative-callable-context.ru.md) |
| Поздняя загрузка статического делегатора | Для обычного alias и alias с `::` консервативная зависимость, созданная до загрузки владельца, вызывает второй запуск при изменении соответствующего ID. Точное снятие зависимости потребует согласованной публикации результата делегатора и индекса. [План](relative-callable-context.ru.md) |
| Нормализация конфигурации | После поздней ошибки прямой `assertShape(&$sections)` уже нормализовал `invokables` и добавил alias в переданный массив. Воспроизведено на обеих PHP. Атомарность этой операции и её типизация при передаче по ссылке требуют определения контракта. [План](configuration-normalization-contract.ru.md) |
| Большие графы alias | Подтверждён квадратичный холодный обход цепи при порядке от конечного ID к началу. Критерии пересмотра — реальная нагрузка сборки и сохранение порядка диагностик, проверки циклов и семантики мутаций. [План](large-alias-graphs.ru.md) |
| Нативные lazy-объекты и Fibers | Нативный и DI ghost возвращают промежуточное `starting`. Нативный и DI proxy выдают одинаковую ошибку неинициализированного свойства во время паузы. Политика синхронизации общего объекта принадлежит отдельному контракту. [План](native-lazy-fiber.ru.md) |
| Опрос доступности атрибутов | Подтверждена стоимость повторных проверок отсутствующих имён. Изменение частоты опроса зависит от согласованного способа уведомления и измеренных расходов в приложении. [План](attribute-availability-performance.ru.md) |

### Срок жизни привязки, скрытой алиасом

В первом публичном сценарии `previous` — обычное значение, во втором — фабрика-объект с отдельно созданным и прогретым результатом. После `alias('previous', 'replacement')` оба запроса возвращают объект `replacement`. После `gc_collect_cycles()` слабые ссылки на прежнее значение, объект фабрики и её прежний продукт остаются живы. При уничтожении контейнера ссылки очищаются. Наблюдение одинаково на PHP 8.4.28 и 8.5.13. [Код воспроизведения](di6-audit-2026-11-21.md#lifetime-of-a-binding-hidden-by-an-alias)

`alias()` меняет маршрутизацию и инвалидирует кеш запрошенных ID. Записи базового кеша и определения принадлежат старому каноническому ID. У публичного API нет операции удаления alias. Для долгоживущего контейнера последствия зависят от числа таких ID и объёма захваченного состояния. При выборе срока освобождения нужно определить владельца скрытой записи, порядок публикации и вызова деструкторов при повторном входе, видимость старого объекта для активного запроса и обработку исключения деструктора. Приёмка должна сохранить допустимость `alias()` поверх существующего ID, результат активного разрешения и идентичность незатронутых сервисов. [Реализация `alias()`](../../src/Container.php) · [Контракт владения](definition-owner-lifecycle.ru.md)

## Безопасность и устойчивость

- Первый проход проверил путь от PSR-7 до DTO и callbacks, включая слияние источников, преобразования, `afterMap`, подстановку аргументов, защиту источников параметров и позднюю автозагрузку. Данные о происхождении HTTP-параметров проверяются на всём наборе затронутых аргументов. Контексты расширений получают публичные параметры. Приложение выбирает DTO, доверенные callbacks, фабрики и валидаторы. [HTTP-обработчик](../../src/Resolver/Attribute/Handler/RequestAttributeHandler.php) · [Защита источников](../../src/Internal/Resolver/Parameter/Request/MappedRequestParameterSourceGuard.php)
- Второй проход проверил переходы от конфигурации и PSR-11 к нативному вызову, защиту системных ID, публикацию кешей при мутациях, исключения и цепочку поставки. В `src` отсутствуют `eval`, десериализация, запуск внешних процессов, файловые записи и сетевые запросы. Диагностика DI отдельно хранит имена и типы. `getPrevious()` и нативная трассировка PHP могут содержать данные расширения, которое выбросило ошибку. [Контейнер](../../src/Container.php) · [Диагностика](../../src/Exception/ResolutionException.php) · [Release workflow](../../.github/workflows/release.yml)
- Контроли отделяют ограничения от дефектов библиотеки. Отказ стандартного адаптера для lazy-класса без backed properties соответствует опубликованному lifecycle. Ошибка инициализации допускает повторную попытку. Magic-методы получают аргументы по правилам PHP, поскольку у выбранного маршрута нет сигнатуры для DI-подстановки. [Lazy-контракт](propertyless-lazy-lifecycle.ru.md) · [Контроль magic](../../tests/Contract/MagicCallableSyntaxContractTest.php)
- Подтверждённых уязвимостей на проверенных путях от HTTP-входа до вызова и создания DTO нет. `composer audit` сообщил ноль advisories и abandoned-пакетов в установленном dev-графе и минимальном production-графе. ## Исправления архитектурных дефектов

- Bootstrap сверяет объявившиеся DI-атрибуты использованных целей после освобождения временных ссылок. Попытка, приостановленная в резолвере, сверяет использованный префикс и после возврата контейнера. [Завершение bootstrap](../../tests/Contract/BootstrapProofRetirementContractTest.php) · [Fiber](../../tests/Contract/BootstrapInFlightFinalizationContractTest.php)
- Сведения о потреблённых атрибутах аргументов конструктора живут до конца текущей попытки. Несовместимая политика отклоняет создание или инициализацию до публикации результата. [Тест конструктора](../../tests/Contract/CompletedConstructorArgumentsContractTest.php)
- `get()` сообщает об отсутствии запрошенного маршрута через PSR-11 NotFound и об ошибке вложенной зависимости через `ResolutionException` с сохранённой причиной. [Проверка PSR-11](../../tests/Contract/PsrLookupFailureContractTest.php)
- Кеш делегатора и его зависимости публикуются с одной версией. Уведомление `notifyExternalEntriesChanged()` адресно обновляет цепочки, включая обновления во время регистрации другого провайдера. [Поздний статический маршрут](../../tests/Contract/StaticDelegatorInvalidationContractTest.php) · [Внешнее обновление](../../tests/Contract/ExternalOwnershipNotificationContractTest.php)
- `alias()` отпускает ставшие недостижимыми определения и базовые значения после публикации маршрута. Версия записи препятствует её восстановлению приостановленным разрешением. [Освобождение](../../tests/Contract/MutationRetirementContractTest.php) · [Активное разрешение](../../tests/Contract/EntryCachePublicationContractTest.php)
- PHPDoc методов `get()` и `make()` отражает допустимые значения для произвольных ID, включая имена классов. [Типы результатов](../../tests/Contract/TypedEntryContractTest.php)
- Граф алиасов переиспользует вычисленные конечные ID при добавлении рёбер. Нормализация передаёт уже проверенный граф сборке контейнера. [Порядок нормализации](../../tests/Contract/DependencyNormalizationContractTest.php) · [Диагностика циклов](../../tests/Contract/AliasConfigurationContractTest.php)
- Фабрика с адресным обнаружением изолирует ошибки необязательных загрузчиков по используемым декларациям. Основная фабрика сохраняет порядок наблюдаемой автозагрузки. [Адресное обнаружение](../../tests/Contract/TargetedAttributeDiscoveryContractTest.php)

Типы исключений, момент освобождения и типы результатов описаны в [руководстве по миграции](../migrations/di6-definitions.ru.md#разрешение-сервисов-и-обновление-метаданных).

| Перестроение поздно загруженного статического делегатора | +1,7% | +2,4% |

Для повторно используемого замыкания задержка выросла во всех четырёх парах обеих версий PHP. Разница абсолютных медиан составила 0,49 мкс на PHP 8.4 и 0,36 мкс на PHP 8.5. Для прогретого `get()` исходные и итоговые диапазоны пересекались. Замеры явной фабрики на PHP 8.4 имели широкий разброс, поэтому из них нельзя вывести устойчивое ускорение.

Отдельный результат выбора маршрута используют общие запросы `get()`. Это вернуло явную фабрику на прямой путь `make()` и сняло наблюдавшееся до оптимизации удорожание. Для делегаторов сбор маршрута запускается при неопределённом владельце. Один подтверждённый нативный маршрут сохраняет точный индекс после следующего перестроения. Первая реализация увеличивала задержку перестроения делегатора с точным ID на 23–26%. Итоговый замер дал 3–5% с пересечением диапазонов в обеих версиях. При сравнении использовались четыре пары процессов на версии PHP для вызова, фабрик и перестроения делегаторов. Графы и финальная проверка обнаружения атрибутов использовали две пары. Графы измеряли только `ContainerFactory::create()`, без последующих проверок результата. Для делегаторов на итерацию выполнялись `set()` и `get()`. Снимки графа и делегаторов предшествовали последним оптимизациям путей, которые эти сценарии не исполняют. Для остальных строк повторный замер использовал итоговое дерево. Синтетические данные характеризуют перечисленные нагрузки.

Для повторения укажите в `COMPONENTA_DI_BENCH_SOURCE` проверяемую копию `src`, а в `COMPONENTA_DI_BENCH_AUTOLOAD` один Composer autoloader с одинаковыми зависимостями. Для сравнения режимов обнаружения установите `DI_BENCH_TARGETED_DISCOVERY=1` только в адресной серии. Скрипты проверяют источник загруженных классов.

На итоговом дереве PHPStan и PHP CS Fixer прошли. Pest выполнил 2 633 теста на PHP 8.4.28 и 2 652 на PHP 8.5.13. Smoke-тест отдельной production-установки с минимальным графом зависимостей прошёл на обеих версиях.
