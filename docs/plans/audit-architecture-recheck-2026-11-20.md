The new cold factory-completion test detected removal of the terminal `$container->get(Config::class);` when explicitly executed on both PHP versions. A standard Pest mutation run revealed that this did not guarantee normal worker selection. The completion case executes the relevant code in a native child process; its companion empty-factory case stops earlier. Parent coverage for the terminal line had 1,928 measured test IDs and 256 class selectors, with no `ContainerFactoryCompletionContractTest` selector.

The complete before-correction run selected only `src/ContainerFactory.php`: **289 total, 271 detected, 18 survivors, zero timeouts or uncovered results**. The terminal-call removal survived. The paired experiment uses the isolated baseline test suite plus the six new core behavior cases; the after run also includes the selector-policy extension. It does not include the other twelve behavior cases integrated into the main checkout. This is a matched single-file mutation experiment, separate from the final complete ordinary test suites below.

The correction adds the source-specific `ContainerFactory.php` to `ContainerFactoryCompletionContractTest` mapping to the existing subprocess policy. It applies only when that test file is registered. Unrelated source selection, `[]` and `null` entries, original input and the measured coverage mask remain unchanged. This repairs the test harness without inventing coverage hits or changing runtime behavior. The policy and its limits are documented in [mutation testing](../../tests/mutation-testing.md).

After the fix, registered-contract runs passed **10 tests / 26 assertions**, and isolated policy runs passed **2 tests / 10 assertions**, on each runtime. Independent review checked source isolation, registration, coverage preservation and both language versions of the policy. ## Security and performance assessment

The reviewed trust boundary treats configuration, autoloaders, factories, attribute handlers and custom providers as application PHP code. Request mapping must not turn request values into that configuration or let them overwrite internal provenance. Tests cover private-context filtering, source conflicts, selected request sources, callback visibility, argument snapshots and later provider replacement. A production-source sink search found no `eval`, unserialization, shell/process execution or file-content read/write calls in `src`; that search supplements the control-flow review and is not a proof of universal security.

Callable visibility follows the target's lexical context, with explicit negative controls for inaccessible child and DI-private methods. Routing snapshots isolate caller-owned reference slots while retaining intended business-object state. Owned exceptions preserve identity and foreign boundary failures preserve their causes. Detached diagnostic payloads avoid retaining runtime reflectors and request objects; native Throwable trace arguments and application logging/redaction remain separate concerns. No new remotely exploitable vulnerability was established by this pass.

Cache review covered revision checks, per-container ownership, stale-write rejection, weak lifetimes and invalidation after runtime changes. Shared `get()` remains a separate fast path. The fresh availability smoke reproduces **24** missing-name loader calls per affected creation after one unavailable attribute is tracked, and **192** after eight; shared hits make zero such calls in the fixture. The previous paired latency comparison and cold-alias measurements retain their documented historical provenance. This pass does not convert concurrent smoke timings into an optimization claim.

## Remaining decisions

The highest-value correctness design remains [bootstrap cleanup/publication](bootstrap-finalization-boundaries.md), because the witness returns a cached object with stale metadata-dependent state. [External-provider ownership](external-provider-ownership.md) needs an explicit stability/change contract before broader invalidation can be justified. Both reports describe failure policy, identity, reentry, destructor timing, compatibility cost and acceptance cases.

[Attribute availability cost](attribute-availability-performance.md) and [large alias graphs](large-alias-graphs.md) remain workload-dependent optimization proposals. Avoid a permanent negative metadata cache or a blind extra polling loop merely to reduce synthetic costs. [Relative callables](relative-callable-context.md), [standalone API policy](standalone-api-surface.md), [normalization atomicity](configuration-normalization-contract.md) and [cross-Fiber lazy publication](native-lazy-fiber.md) require the consumer guarantees described in their reports before implementation. None is silently converted into a breaking change by this audit.
