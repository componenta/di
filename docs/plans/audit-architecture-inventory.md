## 1. Reading the statuses

The tables distinguish implemented decisions, unresolved contracts, conditional investigations and historically rejected approaches. The date and introductory status of the current plan take precedence over old future-tense steps and release gates. An older report's evidence retains its own source/runtime identity even when later work closed the issue.

The [machine-readable inventory](audit-architecture-inventory.json) records the same decision map. The historical set contains **31 Markdown files** in the last complete `docs/audit` tree at `80cb69a59f001a7d9c49af6e254ff3f58ffa8504`: 27 main reports, three evidence indices and one reproduction guide. The directory was removed in `79890e0`, but the immutable Git links below preserve its original text. This inventory transfers every identified architecture decision to maintained plans without restoring the large historical raw-artifact cache to the current tree.

The review also covered all 12 EN/RU `docs/plans` files present at the start of the inventory, four consolidated November 19–20 reports and the supporting review records below. Source pointers H01–H19 and R01–R04 are expanded in §6–7.

## 5. Preserved contracts and unselected extensions

This section preserves historical questions which could otherwise disappear between plans. It does not relabel established behavior as a defect. A future consumer requirement can justify separate design with an explicit new contract.

| Issue | Current report / status | Source and required action |
|---|---|---|
| Header key casing | [request-mapping-examples](request-mapping-examples.md) — **Preserved contract** | H10 §4 and §10. MapHeaders preserves original key casing; Header uses case-insensitive PSR-7 lookup. Universal normalization would need a separately justified API and collision/provenance policy. No such implementation is selected and this difference is not a confirmed defect. |
| Sequential union availability | [php85-callbacks](php85-callbacks.md) — **Preserved contract** | H10 §4 and §10; H12/H13. Simple unions test availability sequentially and choose one candidate or ambiguity before construction. Effectful has() does not imply a globally atomic snapshot. Stronger atomicity needs a provider/snapshot contract and is not an automatic fix; DNF/intersection discovery remains outside scope. |
| Broad native by-reference callable ABI | [relative-callable-context](relative-callable-context.md) — **Unselected extension** | H01 observed contracts; H10 §4; H13 §6. By-reference injection is outside the established DI parameter contract. Fixing tuple ownership or relative scope does not silently promise all native callable forms or reference aliasing. A future extension requires actual consumer semantics and negative controls. |
| General rollback and arbitrary destructor/GC effects | [definition-owner-lifecycle](definition-owner-lifecycle.md) — **Preserved boundary** | H03/H04 retirement; H10 §5 and §10; R04 §8.2. Retirement reports committed publication and synchronous release failures, not rollback of user effects or forced GC. Later release of caller-owned objects is not equivalent to releasing library-owned bootstrap proof; the latter has its own concrete proposal. |
| Explicit creation, requested-ID pipelines and request authority | [definition-owner-lifecycle](definition-owner-lifecycle.md) — **Preserved contract** | H01 §3; H04 excluded false positives; H11 §5. Factories and ClassDefinition own their lifecycle; invokables use their native constructor route. Aliases share base resolution while requested IDs own delegators. Bare PSR request types do not select a request source; protected provenance and native omission remain intentional. Internal mutable collaborators are not shareable container state. |
| Already shared aggregates after dependency mutation | [request-mapping-examples](request-mapping-examples.md) — **Preserved contract** | Current mapping examples and definition lifecycle. Targeted cache invalidation does not promise recursively rebuilding an arbitrary previously returned object graph. afterMap executes before deferred creation and is not replayed on a lazy retry. A larger reactive dependency model would need a separate requirement. |
| Executable extensions and diagnostic disclosure | [bootstrap-finalization-boundaries](bootstrap-finalization-boundaries.md) — **Trust boundary** | H10 §5; H13 §6; H15 §5; R01–R04 security sections. Configuration, autoloaders, callbacks and custom providers are application PHP code; request data does not become executable configuration through the reviewed mapping routes. Private metadata filtering is not a sandbox. Global exception/trace redaction, request-size policy and deployment security remain application concerns; historical clean checks are not timeless vulnerability guarantees. |
| Mutation evidence and optional platform qualification | This inventory — **Verification policy** | H12 §6.3; H13/H15 mutation sections; R02/R03/R04. Keep tool totals, timeouts, focused witnesses, static hypotheses and original-source bugs separate. Direct API coverage is governed by the selected support contract, not by killing every mutant. A consumer smoke on a development PHP does not qualify the full library/toolchain. This is verification policy, not production architecture. |
| Reuse of an authoritative provider availability result | This inventory — **Historical local candidate** | H09 §7 Deferred work. The historical source review named a possible redundant boolean query but did not implement or measure it. It is not an approved architecture project, confirmed current bug or performance gain. Reassess current code only when a future scoped task justifies it. |

## 8. Maintaining the inventory

When an architecture decision is selected, update its status, owner, compatibility and evidence in the topical plan, then synchronize this inventory and the [main index](README.md). Preserve the original motivation and rejected alternatives when implementing it; attach new acceptance results to their own source/runtime.

Recording an open decision completes documentation only. Executed evidence belongs to its separately attributed recheck or supplement; documenting a conditional alternative neither implements that design nor authorizes it.
