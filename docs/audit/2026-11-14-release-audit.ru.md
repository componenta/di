# Полная повторная проверка DI и аудит релиза v5.0.6 — 2026-11-14

[English version](2026-11-14-release-audit.md)

## Область проверки и результат

Проверка начата с `main` на коммите `1a1a0a8772eaabc2a80016744b123ebcd98975ca`; последним опубликованным релизом был `v5.0.5` на `a56f3d70dd56bdd62947b6c322aa878e8a76ef4c`. Независимые проверки кода и тестов охватили выбор записей, определения, aliases, общие кеши, отложенные фабрики и делегаторы, внешние контейнеры, подготовленные и нативные callable, разрешение параметров, композицию и фазы атрибутов, HTTP mapping, исключения, время жизни объектов, Fibers и мутации при повторном входе.

Четыре дополнительных дефекта воспроизведены падающими тестами публичного поведения, исправлены без изменения архитектуры и отправлены отдельными коммитами. В релиз также входят семь прежних исправлений runtime после предыдущего выпуска. Совокупное изменение является совместимым patch: PHP `^8.4`, ограничения зависимостей и поддерживаемый публичный API сохранены. Полный состав приведён в [описании v5.0.6](../releases/v5.0.6.ru.md).

Строгая проверка Composer пройдена; аудит зависимостей не выявил advisories и заброшенных пакетов. PHPStan завершил анализ через PHP-реализацию, поскольку необязательное расширение turbo не может загружаться в статический CLI. Это ограничение запуска не помешало анализу.

Локальный граф vendor использует workspace/path-манифесты Config 3.0.0, Reflection 2.0.1 и Validation 3.0.1. Их ссылки на исходники (`dcd2189`, `62aca657`, `8f88878`) совпадают с сохранённой релизной установкой опубликованных пакетов. Новая установка опубликованных зависимостей относится к описанным ниже релизным проверкам GitHub Actions и не заявляется как выполненная локальная проверка.

[JSON с доказательствами](2026-11-14-release-evidence.json) фиксирует точные идентификаторы и контрольные суммы исходного кода, версии PHP, команды и результаты. Диагностика согласованности сравнивает возвращаемые значения после истории мутаций времени выполнения и падает при неожиданных исключениях. Принадлежность ошибок и идентичность общих объектов отдельно проверяют контрактные тесты. Число сравнений не является mutation score; прохождение конечного набора тестов не доказывает корректность при любых побочных эффектах расширений.

**На момент подготовки отчёта релизные проверки GitHub Actions ещё ожидаются.** [Release workflow](../../.github/workflows/release.yml) должен проверить точный коммит релиза с опубликованными зависимостями на Linux PHP 8.4/8.5 и Windows PHP 8.4, затем пройти покрытие ≥80% и mutation score ≥85% до публикации `v5.0.6`. Прежние результаты покрытия и mutation testing остаются историческими доказательствами и не выдаются за новые результаты.

## Включённые прежние исправления и отсеянные ложные срабатывания

[Проверка 13 ноября](2026-11-13-full-library-recheck.ru.md) описывает семь runtime-коммитов между `v5.0.5` и начальной ревизией: `4621f9e`, `fedf953`, `5fe8cc0`, `7da5163`, `eb7818d`, `fce3f17`, `7dc88a4`. Они исправляют маршруты aliases, обнаружение и исполнение параметров, поиск вложенно зарегистрированных внешних зависимостей, резервную доступность классов и источников, фиксацию использованного плана и идентичность кеша нативных callable. `71a8430` исправляет выбор исходного кода при загрузке бенчмарков.

В остальных проверенных путях дополнительных подтверждённых локальных дефектов не найдено. Различие общего `get()` и свежего `make()`, жизненный цикл явного `ClassDefinition`, отсутствие поддержки передачи параметров по ссылке и различия статического состояния нативных callbacks остаются намеренными контрактами. Холодные, прогретые и некешируемые проверки сохраняют актуальные входные данные, конфликты источников и границы исключений; кеш метаданных не должен подменять значения зависимостей времени выполнения.

## Архитектурные решения для новой ветки

[Спецификация владения определениями](../plans/definition-owner-lifecycle.ru.md) готова к реализации в следующей major-версии. Центральная таблица неизменяемых привязок и внутренний барьер освобождения закрывают три всё ещё воспроизводимых дефекта 5.x: удержание устаревшей конфигурации фабрики после смены владельца; расхождение общего и свежего разрешения после исключения деструктора освобождаемой фабрики; незавершённую инвалидацию семейства aliases после исключения деструктора кешированной обёртки. Ни один из них не заявлен исправленным в `5.0.6`.

[Спецификация callbacks](../plans/php85-callbacks.ru.md) также содержит готовые контракты общего механизма первого аргумента, `Transform`, callback-формы `SetUp` и выбора простых union-типов. Реализация библиотеки может идти независимо от E1. Это условие всё ещё блокирует окончательный минимальный patch PHP и гарантию затронутых first-class references из trait: проверенный стабильный исходный код `8.5.12` не содержит исправления, а `8.5.13RC1` не является стабильным релизом. План определяет ограниченную проверку исходников и точного бинарного PHP, необходимую для снятия блокировки.

[План производительности проверки атрибутов](../plans/attribute-availability-performance.ru.md) пока не разрешает production-реализацию B2: требуются данные о затратах приложения и контракт синхронизации. Прототип A меняет наблюдаемое поведение автозагрузки; C не выбран. Работа над владением обоснована дефектами корректности и времени жизни, а не неизмеренным обещанием ускорения. Все три плана сохраняют полные русские переводы.

Запрошенная последовательность: опубликовать проверенный совместимый patch после релизных проверок, затем создать отдельную ветку рефакторинга и реализовывать готовые срезы планов с регрессионными тестами и проверкой соответствия спецификации. API следующей major-версии в этот релизный аудит не включены.
