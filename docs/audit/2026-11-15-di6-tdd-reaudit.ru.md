## 2. Что именно означает TDD-проверка в этом отчёте

Для найденных слабых проверок использовался следующий цикл: осмысленно испортить поведение в изолированной копии, убедиться, что старый тест пропускает эту поломку, усилить наблюдение, получить падение по нужной причине и восстановить исходную реализацию до GREEN. Новый lifetime-тест также сначала запускался против удерживающего callable варианта. В тесты не вставлялись искусственные `fail()` ради формального RED.

**Реально исполненный содержательный RED есть у 10 уникальных деклараций.** Проверены **11 разных намеренных поломок production** и **6 подмен native fixtures посторонними fatal errors**. Остальные **737 деклараций** получили ручной разбор контракта, oracle и контрпримера, но отдельный RED для каждой из них не выполнялся. Полный успешный suite и общий mutation score не превращают эту работу в 747 индивидуальных циклов RED/GREEN и не доказывают, что исторически каждый тест был написан первым.

Это разделение сохранено машинно: записи `executed_meaningful_RED` и `reasoned_counterexample` не смешиваются. Фраза «каждый тест проверен» далее относится к полному индивидуальному review; она не означает несуществующую историю запусков.

Дополнительно проверена семантика самих assertions в установленном Pest. `toThrow(Class::class, 'text')` проверяет совместимый класс и подстроку сообщения. `toThrow($exceptionObject)` проверяет совместимый класс и точное сообщение, **но не идентичность объекта исключения**. Завышенные формулировки в review исправлены. Там, где контракт теста не требует identity, новый production-дефект из этого различия не выведен.

### T01. Нативная ошибка должна иметь нужную причину

В [Php85AttributeCallableContractTest.php](../../tests/Contract/Php85AttributeCallableContractTest.php) проверялись ненулевой exit code, `Fatal error` и sentinel фазы компиляции. Подстановка шести fixtures с посторонними fatal errors оставляла **6 passed / 18 assertions**. Усиленная проверка на тех же повреждённых fixtures даёт **6 failed / 24 assertions**. С исходными fixtures полный файл проходит на PHP 8.5: **11 tests / 35 assertions**.

Теперь отдельно проверяются запрещённые операции constant expression, захват переменной, нестатическая closure, динамическое имя функции и недопустимая magic reference. Это проверка достоверности platform-границы, а не обнаружение шести ошибок PHP или DI. На PHP 8.4 предусмотренные native cases пропускаются.

### T02, T05, T08 и T09. Положительное наблюдение перед отрицательным выводом

В [AttributePlanSelectionContractTest.php](../../tests/Contract/AttributePlanSelectionContractTest.php) исходный порядок fixture намеренно изменён с уже корректного на требующий перестановки. Удаление `after`-связей теперь обнаруживается; ожидаемый результат задан независимо от алгоритма production.

В [AttributeRuntimeIsolationTest.php](../../tests/V5/AttributeRuntimeIsolationTest.php) недостаточно получить два объекта: handler должен действительно отработать на каждом. Удаление dispatch раньше давало GREEN, теперь падает на счётчике первого вызова. Это сохраняет смысл прежнего теста, который ловит повторное использование runtime-экземпляра атрибута внутри handler.

В [DeferredExtensionSpecificationTest.php](../../tests/V5/DeferredExtensionSpecificationTest.php) два одинаковых resolver заменены двумя различимыми маршрутами уже существующего DTO: attribute value и fallback. Пропуск service-ID registration теперь приводит к ошибке разрешения fallback. Отдельная mutation пропускает closure attribute-definition factory: resolver всё ещё способен читать reflection attribute, поэтому без нового счётчика тест проходил бы. Итоговый тест требует один вызов factory и оба независимых значения.

В двух декларациях [InternalContextLeakageTest.php](../../tests/V5/InternalContextLeakageTest.php) пустой массив ключей делал цикл проверки префикса пустым. Теперь оба наблюдателя должны видеть `value` и `ServerRequestInterface::class`. Две разные mutations — повышение приоритета generic array resolver и возврат пустого публичного object context — проходят старые assertions и отвергаются усиленными.

Для этих шести production-поломок сохранены **48 изолированных выполнений**: четыре фазы на PHP 8.4 и 8.5. Это число запусков, а не число уникальных деклараций. Полные изменённые файлы также проходят на обеих версиях.

### T04. Проверка lifetime при живом исключении

Новая декларация в [ExceptionPayloadContractTest.php](../../tests/Contract/ExceptionPayloadContractTest.php) сохраняет `InvalidCallableException`, освобождает входной callable и проверяет `WeakReference` после GC. Три варианта охватывают closure capture, некорректный callable object и receiver массива метода.

Синтетическое добавление приватного поля, сохраняющего исходный callable, не обнаруживалось **всем исходным PHP 8.5 suite: 1462 tests / 24 033 assertions**. Новые три случая дают RED на обеих версиях PHP; исходная реализация проходит полный файл: **14 tests / 61 assertions**.

На время проверки устанавливается `zend.exception_ignore_args=1`, прежнее значение восстанавливается в `finally`. Проверяемая гарантия относится к собственному payload DI. Нативный trace и цепочка `previous` могут владеть аргументами и прикладными данными; очистка всего объекта `Throwable` этим тестом не обещается.

### T06 и T07. Guard должен запрещать ровно то действие, для которого существует

В [RuntimeMutationRecoveryContractTest.php](../../tests/Contract/RuntimeMutationRecoveryContractTest.php) добавлен независимый вложенный external lookup с отдельным значением и наблюдаемым числом обращений. Замена guard, привязанного к service ID, одним глобальным guard раньше проходила полный suite использованного среза, а теперь нарушает положительный контроль. Исходный сценарий same-ID recursion и успешного восстановления сохранён.

Этот старый full-suite эксперимент выполнен на фактическом срезе **`f2fb19e`**, а не на исходном `114949c`. Для 411 tracked source/test/config-файлов восстановленного снимка сверены Git blob bytes; расхождений нет. Даты и название baseline review не подменяют происхождение реально исполненного кода.

В [RuntimeMutationContractTest.php](../../tests/Contract/RuntimeMutationContractTest.php) loader объявляет уникальный alias и считает вызовы. Ослабление ранней проверки protected ID с `OR` до `AND` сохраняет последующий exception, но успевает запустить autoload. Старый тест проходил; новый требует ноль вызовов и отсутствие объявленного класса. Loader снимается в `finally`.

Два широких запуска этого эксперимента упали в другом, ещё не исправленном memory-тесте. Они **не засчитаны** как доказательство T07. Для T07 используются отдельные целевые old-GREEN / new-RED / restored-GREEN на обеих версиях PHP.

## 4. Memory-проверка: усиление без ложного RED

В [CallableCaseCacheRetentionContractTest.php](../../tests/Contract/CallableCaseCacheRetentionContractTest.php) для каждой формы выполняются 8192 варианта регистра. Помимо удержанной памяти проверяется точная сумма результатов, чтобы пропуск исполнения не считался оптимизацией. Удаление нормализации method-name и string-callable — две независимые production mutations; обе пропускались исходным тестом.

Расширенный первоначальный вариант выявил собственную нестабильность в полном suite. На seed `1794737895` корректная реализация показывала **2 228 024 bytes** при границе **2 097 152 bytes**. Это воспроизводилось и с обычным bootstrap; GitHub CI также показал эту причину отказа. Увеличивать допустимый предел на основании такого результата было бы необоснованно.

Независимый native-only контроль, использующий `is_callable()` и `call_user_func_array()` без DI в цикле, показал **1 245 088 bytes** при первом обходе новых написаний и **0 bytes** при повторном. Гипотеза о Composer `missingClasses` отвергнута: его размер оставался нулевым. Установленная причина искажения — процессное состояние native lookup, попадавшее в измерение контейнерного кеша.

Исправление прогревает весь набор написаний на временном контейнере, освобождает его, выполняет GC и измеряет **новый контейнер**. Прогрев измеряемого контейнера мог бы спрятать поломку его кеша, поэтому так не сделано. Лимит остаётся **2 MiB**. Обе mutations после этой правки продолжают падать с ростом **5 962 768 bytes**, восстановленная реализация проходит целевые и полные прогоны. Освобождение временного контейнера проверено отдельным WeakReference-контролем.

Это исправление методики теста. Числа не являются замером экономии памяти приложения и не доказывают новый speedup DI: production в этом проходе не менялся.

## 5. Архитектура и безопасность

### Владение состоянием и публикация изменений

Свежий review [Container](../../src/Container.php), [CompositeResolver](../../src/Resolver/Entry/CompositeResolver.php), definitions, alias routing и retirement сохраняет действующие границы: validation, публикация binding, invalidation и освобождение прежних объектов имеют разные обязанности. Проверены повторный вход через autoload/destructors, alias retarget, текущий provider lookup, сохранение независимых shared entries и восстановление после ошибок. Обнаруженные T06/T07 усиливают наблюдаемость этих контрактов; они не показывают уязвимость в текущей реализации.

### Метаданные и данные текущего вызова

[ParametersResolver](../../src/Resolver/Parameter/ParametersResolver.php), [AttributePlanBuilder](../../src/Attribute/Composition/AttributePlanBuilder.php) и [ObjectPipeline](../../src/Object/ObjectPipeline.php) проверены на разделение стабильного плана и текущих значений. Closure и `ReflectionObject` не должны удерживать runtime ownership общим именованным кешем; mutable composition rules требуют свежей оценки. Тесты используют конкретные ожидаемые значения, замены bindings и WeakReference, а не одно только равенство cached/fresh путей.

Семантические массивы [AttributeDefinition](../../src/Attribute/Composition/AttributeDefinition.php) и callable-массивы [PreparedCallable](../../src/PreparedCallable.php) фиксируют слоты PHP references. Сам объект handler, rule или receiver сохраняет identity и текущее состояние. Глубокое клонирование здесь было бы изменением контракта, а не локальным исправлением.

### Request mapping и публичные контексты

[MappedRequestParameterSourceGuard](../../src/Internal/Resolver/Parameter/Request/MappedRequestParameterSourceGuard.php) проверяет конфликтующие name/type-key до `resolveParameter()` пользовательского resolver, factory или тела. Metadata preflight может вызывать `supports()`; гарантия не запрещает любые обращения к объекту resolver до guard. Тесты включают отрицательные случаи и счётчики побочных действий. [InternalContextLeakageTest](../../tests/V5/InternalContextLeakageTest.php) теперь дополнительно исключает пустое наблюдение.

Mapped HTTP transport, явные программные параметры и opt-in explicit `ClassDefinition` имеют разные предусмотренные правила. Прикладная schema validation зависит от установленного provider. PHP definitions, callbacks, attribute constructors и autoloaders остаются доверенным исполняемым кодом приложения; DI не предоставляет для них sandbox. Из наличия callback-вызовов в библиотеке не сделан вывод о удалённом выполнении кода злоумышленника.

### Поздняя загрузка и завершённые фазы

Revision refresh и [CompletedAttributeGuard](../../src/Internal/CompletedAttributeGuard.php) проверены вместе с cold/warm, cached/fresh и поздним обнаружением классов. Несовместимое изменение уже исполненной семантики отклоняется; завершённые handlers не переигрываются. Eager/lazy/proxy идут через общий pipeline, а неуспешная deferred initialization получает отдельное состояние новой попытки.

Это не транзакционный откат произвольных прикладных side effects и не доказательство всех возможных Fiber/autoload-расписаний. Конкретные рассмотренные границы и контрпримеры указаны для каждого теста в реестре.

### Вывод об архитектуре

Новой задачи, требующей архитектурного решения, этот проход не обосновал. Все подтверждённые изменения улучшают тесты внутри существующих контрактов. Поэтому отдельный план перестройки API, кешей или lifecycle не предлагается. Существующие планы других аудитов сохраняют собственные предпосылки; отсутствие новой задачи здесь не означает их автоматическое закрытие.

## 7. Ограничения и воспроизводимость

Полное ручное чтение, успешные suites, coverage и mutation testing решают разные задачи. Зелёный suite показывает согласованность с текущими assertions; положительные контрпримеры демонстрируют, что конкретная ошибка действительно наблюдается. Ни один из этих слоёв сам по себе не доказывает отсутствие всех возможных багов.

Изолированные доказательства дополнительно проверяли происхождение загруженных классов и eager functions. Оптимизированный Composer classmap может указывать на другой checkout, даже если рабочий каталог выглядит правильным. Для parameter/object experiments проверены 159 существующих mappings dev classmap и шесть функций; у полного lifetime-эксперимента проверены 168 загруженных деклараций и те же шесть функций. Это разные метрики, их нельзя складывать или подменять друг другом.

Первоначальная попытка изоляции native tests с symlink на Pest package загрузила исходный checkout; такая bootstrap-ошибка исключена из RED. Устаревшая classmap-запись в первом parameter experiment также исправлена до валидных контрольных запусков. Сам факт ненулевого exit code не считался доказательством нужной поломки.

Evidence сохраняет mutations/patches, source/test hashes, команды, фактические пути и stdout. Абсолютные scratch-пути фиксируют происхождение проведённых запусков; для повторения на другой машине следует подставить свои checkout и PHP binaries. Материалы review содержат актуальную привязку каждой декларации к runtime case и результату обоих итоговых JUnit.

Новый no-dev consumer, `componenta/app` и прикладные latency/throughput-замеры в этом проходе не запускались: production и dependencies не менялись, а отдельного риска их поведения эти тестовые изменения не создали. Результаты предыдущего аудита доступны как исторические доказательства для его снимков.

PHP constraint остаётся **`^8.4`**. Native PHP 8.5/E1 сохраняет отдельную feature-границу; она не превращается в блокировку всего релиза DI6.
