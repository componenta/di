## 1. Дефект, последствия и выбранное исправление

Для допустимого нативному механизму класса без сохраняемого свойства экземпляра выделение ghost/proxy в PHP может вернуть обычный объект и ни разу не вызвать переданный initializer или фабрику backing-объекта. Это происходит у пустых классов, классов только со статическими свойствами и классов только с виртуальными property hooks. Исходные [наблюдения](2026-11-15-propertyless-lazy-evidence.json) и [план решения](../plans/propertyless-lazy-lifecycle.ru.md) описывают поведение runtime и альтернативы.

Через DI это позволяло успешно опубликовать shared-объект, у которого не выполнились конструктор, `SetUp` либо явно настроенная фабрика продукта `Make`. `NoConstructor` не оправдывает потерю setup: этот атрибут подавляет только конструктор. Инициализация или валидация приложения, помещённая в эти callbacks, могла быть пропущена; конкретная эксплуатация в прикладном проекте этим аудитом не установлена.

Стандартный [`ProxyFactory`](../../src/ProxyFactory.php) теперь проверяет класс перед `newLazyGhost()` или `newLazyProxy()`. Допустимый для нативного механизма класс без сохраняемого свойства экземпляра получает `ResolutionException` с каноническим именем класса в `serviceId`, стратегией в сообщении и без искусственного предыдущего исключения:

```text
Cannot create native lazy ghost for class "Example": no backed instance properties; use eager construction instead.
```

Для proxy используется текст `virtual proxy`. Заготовка целевого объекта не выделяется, поэтому адаптер не может вызвать лишний деструктор цели или незаметно потерять её callback. Повторные неудачные разрешения не публикуют незавершённый shared-сервис. Autoload класса и эффекты расширений, произошедшие до входа в адаптер, не откатываются.

Немедленный eager fallback не выбран. Он изменил бы время выполнения callbacks и возникновения ошибок; уже выделенная обычная proxy-заготовка дополнительно способна вызвать лишний деструктор. Принятый вариант устраняет дефект локально и сохраняет самостоятельность пользовательских реализаций фабрики.

## 2. Реализация и архитектурная граница

Исполняемый production-код изменён в одном файле: 41 добавленная строка в `src/ProxyFactory.php`. Оба публичных входа используют одну закрытую проверку метаданных. Ещё четыре исходных файла содержат только изменения PHPDoc: два интерфейса ленивых фабрик и атрибуты `Lazy`/`Proxy`. Сравнение токенов на обеих локальных версиях PHP подтвердило неизменность исполняемых токенов в этих четырёх файлах. Новые публичные сигнатуры, реестр контейнера, стратегия, feature flag и кеш не добавлены.

| Граница | Реализованное поведение |
| --- | --- |
| Свойство, поддерживающее ленивость | Подходит нестатическое, невиртуальное свойство экземпляра. Сохраняется поддержка readonly, promoted и backed-hook свойств. |
| Наследование | Проверяется вся цепочка родителей, включая private-свойства, отсутствующие в reflection конечного класса. Сохраняемое свойство только у прародителя продолжает поддерживаться. |
| `stdClass` | Пустой `stdClass` и пустые потомки отклоняются; пользовательский потомок с сохраняемым свойством экземпляра поддерживается. Возможность добавить динамическое свойство позже не создаёт нативную точку ленивой инициализации. |
| Другие ограничения PHP | Отсутствующий класс сохраняет ошибку создания reflection. Интерфейсы, traits, абстрактные классы, enum и неподдерживаемая внутренняя иерархия сохраняют нативный отказ выделения и прежнюю DI-нормализацию с нативным `previous`. Сохраняемое свойство не отменяет запрет внутреннего предка. |
| Видимость конструктора | `isInstantiable()` не используется как сокращённая проверка. Private/protected конструктор сам по себе не запрещает допустимое нативное ленивое выделение. |
| Чтение метаданных | Значения свойств не читаются, hooks не вызываются, объект не создаётся, аргументы пользовательских атрибутов не вычисляются. |
| Поддерживаемые callbacks | Сохраняются отложенный вызов, identity исключения callback, повторная попытка и нативная identity ghost/proxy. |
| Пользовательская фабрика | Сохраняется делегирование выбранному `ProxyFactoryInterface`. Новое ограничение принадлежит стандартному нативному адаптеру. |

Проверка свойств выполняется при запросе новой нативной оболочки. Она не выполняется на каждом попадании shared-`get()` или обращении к свойству. После обнаружения сохраняемого свойства повторный перебор свойств прекращается; проход по предкам продолжается для проверки внутренней иерархии. Численное ускорение или снижение памяти не заявляется: выигрыш состоит в правильном жизненном цикле и диагностируемой границе возможностей. Постоянный кеш без измеренной необходимости добавил бы состояние и вопросы инвалидирования к небольшой проверке метаданных.

Диагностические поля содержат цель и стратегию, без объектов сервиса и callback. Нативный trace PHP остаётся отдельным механизмом удержания: при `zend.exception_ignore_args=0` сохранённое исключение может удерживать аргументы callback. Поэтому проверки освобождения захватов временно устанавливают `zend.exception_ignore_args=1`, восстанавливают прежнее значение и проверяют освобождение при удерживаемом исключении. Исправление не очищает нативные traces.

## 5. Миграция затронутых приложений

Изменение совместимости намеренное: ранее успешный, но неинициализированный результат нативного ленивого создания теперь сразу вызывает конкретную DI-ошибку. Следует выбрать требуемый приложению путь инициализации:

1. **Обычное eager-создание через reflection:** убрать соответствующий Lazy/Proxy-маркер класса или точки внедрения. Обычный pipeline по-прежнему выполняет property injection и setup. `NoConstructor`, если оставлен, подавляет только конструктор. Одна замена `get()` на `make()` атрибуты не отключает.
2. **Явная обычная фабрика:** инициализировать возвращаемый продукт внутри неё. Контейнер не переинтерпретирует атрибуты непрозрачного результата после возврата; один class-level `Proxy` не оборачивает его автоматически.
3. **Явный `ClassDefinition`:** использовать конструктор и упорядоченные инструкции `call()`. Определение намеренно игнорирует DI-атрибуты, включая `SetUp`, `Inject`, `Lazy`, `Proxy` и `NoConstructor`. Нужный setup переносится в явные вызовы; fallback по типу остаётся opt-in.
4. **Пользовательская proxy-фабрика:** выбрать независимо проверенную реализацию, которая поддерживает нужную цель и сохраняет действующие deferred-callback-контракты. Проверка стандартного адаптера не становится глобальным запретом.

Например, необходимый публичный метод `initialize()` можно настроить явно:

```php
use Componenta\DI\Definition\ClassDefinition;

$container->set(
    Service::class,
    ClassDefinition::create(Service::class)->call('initialize'),
);
```

Аргументы конструктора и метода следует передать существующим API определения. Добавлять бессмысленное свойство только ради запуска нативной ленивости не рекомендуется.
