| Участок | Коммит | Результат |

DefinitionAwareResolverInterface и прежние карты регистраций/владельцев удалены из исходников и тестов. Пользовательские стратегии используют DefinitionResolverInterface; публичные конструкторы определений и сигнатуры мутаций Container сохранены. Container по-прежнему принимает отдельный fallback resolver и оборачивает его в composite. Не добавлены второй цикл разрешения аргументов, универсальные транзакции, публичные возвращаемые держатели освобождаемого состояния, долговременная очередь уничтожения или принудительный production GC.

Все четыре мутации следуют порядку валидация → публикация → полная инвалидация затронутого состояния → освобождение. Деструктор, вызванный окончательным освобождением, может повторно войти в контейнер или приостановиться только после завершения записей внешней мутации. MutationRetirementException предоставляет ID зафиксированной мутации и упорядоченные причины; первая причина доступна через `getPrevious()`. Существующие исключения Componenta сохраняют идентичность, поэтому независимо зафиксированная вложенная мутация может передать это исключение через внешнюю валидацию, которая ещё ничего не опубликовала. Различие описано в [руководстве миграции определений](../migrations/di6-definitions.ru.md).

## Измерение затрат

Оба дерева исходников использовали один PHP binary, настройки `-n`, установку зависимостей и benchmark-файл. Загрузчик выбранных исходников проверяет пути production-классов и функций даже при оптимизированном Composer classmap. Каждый процесс выполняет семь раундов и возвращает медиану; между раундами вызывается GC, обычные операции имеют 20 000 итераций за раунд. Runtime-контроли завершаются до создания графов контейнеров, используемых только новыми возможностями.

Первые измерения построения заметно колебались, поэтому они повторены с 5000 построений за раунд, двумя медианами процессов на версию/runtime в порядке baseline–ветка–ветка–baseline. Первый baseline-процесс PHP 8.4 пересёкся с короткой диагностикой и заменён изолированным запуском; исходное значение исключено. Строки построения ниже используют медиану медиан процессов. Все значения случаев и проверки источников доступны в evidence JSON.

## Миграция и оставшиеся условия

Полные руководства: [определения](../migrations/di6-definitions.ru.md) / [English](../migrations/di6-definitions.md) и [callbacks/unions](../migrations/di6-callbacks.ru.md) / [English](../migrations/di6-callbacks.md). В них описаны удалённые API расширений и конструкторы, момент нормализации/допуска, идентичность снимков, присоединение, зафиксированные ошибки, расширение свойства подклассов SetUp, прямое создание SetUpRunner, связывание источника, нативный синтаксис и поведение union.

- **E1 остаётся открытым.** До выбора итогового Composer floor, alias `6.0.x-dev` и обещания поддержки/выпуска DI 6 нужно проверить точный бинарный файл официально выпущенного patch PHP 8.5, содержащего исправление нативных first-class references в trait. [Спецификация платформы](../plans/php85-callbacks.ru.md) содержит upstream-доказательства и ограниченную задачу приёмки.
- **Доступность атрибутов B2 остаётся условной.** По-прежнему необходимы доказательства затрат приложения и полный пересмотренный контракт синхронизации. Исправленный контракт опроса сохранён; широкий рефакторинг доступности не выполнялся.
- **Callback-преобразование request-to-DTO остаётся отложенным.** Источник, порядок, provenance и API требуют отдельной спецификации. Существующая защита источников request действует в реализованных callback-путях.

Это явные оставшиеся условия, а не незавершённая реализация определённых готовых участков библиотеки. [Указатель планов](../plans/README.ru.md) и обе полные версии спецификаций теперь отличают выполненную работу от этих условий.

## Воспроизведение

Выполнить следующие команды каждой документированной версией PHP в репозитории с установленными зависимостями разработки:

```sh
php -n vendor/bin/pest --compact
php -n vendor/bin/phpstan analyse --no-progress --memory-limit=1G
php -n vendor/bin/php-cs-fixer fix --dry-run --diff --using-cache=no
php -n docs/audit/reproductions/MutationParity.php
```

Для измерений задать `COMPONENTA_DI_BENCH_AUTOLOAD` общим vendor-autoloader, а `COMPONENTA_DI_BENCH_SOURCE` — исходниками неизменяемого релизного checkout или ветки. Последовательно выполнить RuntimeBench, GeneratedVsReflectionBench, BuildPhasesBench и ParameterPlanBench с указанными выше итерациями. `DI_BENCH_CASES` при необходимости выбирает случаи RuntimeBench через запятую; итоговые полные измерения RuntimeBench выполнены без фильтра.
