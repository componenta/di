# Componenta DI v5.0.6

[Русская версия](v5.0.6.ru.md)

Prepared on 2026-11-14. Publication requires the fresh checks of the [Release workflow](../../.github/workflows/release.yml) on the exact release commit; the local results below do not claim that this hosted run has already passed.

## Version and compatibility

This patch contains correctness fixes following [`v5.0.5`](https://github.com/componenta/di/releases/tag/v5.0.5), including the seven runtime corrections already on `main` before the November 14 recheck and four newly reproduced defects. No supported public API or dependency constraint changes. PHP remains `^8.4`; valid configuration requires no migration. Under [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html), these compatible corrections justify `5.0.6`.

`get()` still returns shared values and `make()` still creates fresh objects. Neither proposed DI 6 features nor definition-ownership replacement are included.

## New corrections from the full recheck

| Area | Corrected behavior |
| --- | --- |
| Native callable preparation | Foreign failures raised while resolving or autoloading a native callable are normalized to the existing DI exception boundary, retaining the original cause. Exceptions thrown after entering the callable body still propagate unchanged. |
| Availability after external lookup | `has()` refreshes alias routing after an external container's callback mutates aliases. Its answer reflects the resulting target; a nested retarget to a protected core ID cannot bypass the protected-service rule. |
| HTTP DTO source discovery | A later attribute can autoload a source annotation skipped earlier on the same or another constructor parameter. The source guard now reinspects loaded declarations before factory dispatch, rejects conflicting mapped input on the first call, and does not perform extra autoload attempts. |
| Deferred factory reentrancy | Deferred factory resolution snapshots the validation flag together with the selected factory before owner lookup invokes application code. Nested replacement cannot pair the old factory with the new registration's validation policy. Independently completed nested changes remain committed. |

Each defect has a regression that failed before its fix. The [November 14 audit](../audit/2026-11-14-release-audit.md) identifies the commits, tests and verification results.

## Earlier main-branch fixes included in this release

The [November 13 full recheck](../audit/2026-11-13-full-library-recheck.md) documents these seven corrections, which were not part of the published `v5.0.5` tag:

- Refresh alias routing after external ownership queries during resolution.
- Keep parameter execution slots coherent with attribute discovery.
- Discover deferred dependencies registered during a reentrant external-container callback before invalidation completes.
- Recognize classes declared by a fallback availability probe when validating definitions and attribute selectors.
- Enforce HTTP DTO source conflicts after that fallback discovery.
- Record the attribute plan actually consumed by handlers, rather than a later plan whose handlers never executed.
- Share native static-callable plans across class-name case variants without changing opaque service-ID matching.

The benchmark bootstrap also selects classes and autoloaded helper functions from the requested checkout when the dependency installation has an optimized classmap. This is a harness correction, not a claimed application speedup.

## Known limitations and subsequent work

Three definition-lifecycle failures remain outside this patch: obsolete factories can stay retained after switching definition-owner type; a throwing retired-factory destructor can leave `get()` and `make()` observing different states; a throwing cached wrapper destructor can interrupt alias-family invalidation. The [central-ownership and retirement specification](../plans/definition-owner-lifecycle.md) is ready for the next-major branch and explicitly addresses all three.

The [callback specification](../plans/php85-callbacks.md) is ready for implementation of the shared binder, `Transform`, callback `SetUp` and deterministic simple-union autowiring. Its E1 gate still blocks the final PHP patch floor and the affected native trait-callable support promise. The [availability plan](../plans/attribute-availability-performance.md) leaves B2 conditional on application evidence and a complete synchronization contract; it is not an approved transparent optimization. All plans retain complete Russian translations.
