# Componenta DI v5.0.6

[English version](v5.0.6.md)

Подготовлено 2026-11-14. Публикация требует нового прогона [Release workflow](../../.github/workflows/release.yml) на точном коммите релиза; приведённые ниже локальные результаты не означают, что этот прогон GitHub Actions уже завершился успешно.

## Версия и совместимость

Этот patch включает исправления после [`v5.0.5`](https://github.com/componenta/di/releases/tag/v5.0.5): семь исправлений runtime, уже находившихся в `main` перед повторной проверкой 14 ноября, и четыре заново воспроизведённых дефекта. Поддерживаемый публичный API и ограничения версий зависимостей не меняются. PHP остаётся `^8.4`; корректная конфигурация не требует миграции. По [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html) такие совместимые исправления обосновывают версию `5.0.6`.

`get()` по-прежнему возвращает общие значения, а `make()` создаёт новые объекты. Предлагаемые возможности DI 6 и замена модели владения определениями в релиз не входят.

## Новые исправления полной повторной проверки

| Область | Исправленное поведение |
| --- | --- |
| Подготовка нативного callable | Внешние ошибки при разрешении или автозагрузке нативного callable приводятся к существующей границе исключений DI с сохранением исходной причины. Исключения после входа в тело callable по-прежнему распространяются без изменения. |
| Доступность после внешнего поиска | `has()` обновляет маршрут alias, если callback внешнего контейнера изменяет aliases. Ответ соответствует итоговому целевому ID; вложенное перенаправление на защищённый ID ядра не обходит правило защиты сервисов. |
| Обнаружение источников HTTP DTO | Поздний атрибут может загрузить source-аннотацию, пропущенную ранее на том же или другом параметре конструктора. Проверка источников теперь повторно читает загруженные объявления до вызова фабрики, отклоняет конфликтующие входные данные уже при первом обращении и не добавляет попыток автозагрузки. |
| Повторный вход при разрешении отложенной фабрики | Разрешение отложенной фабрики фиксирует флаг проверки вместе с выбранной фабрикой до поиска владельца, способного вызвать прикладной код. Вложенная замена не смешивает старую фабрику с политикой проверки новой регистрации. Независимо завершённые вложенные изменения сохраняются. |

Каждый дефект закрыт регрессионным тестом, падавшим до исправления. [Аудит 14 ноября](../audit/2026-11-14-release-audit.ru.md) указывает коммиты, тесты и результаты проверки.

## Ранее внесённые исправления main, включённые в релиз

[Полная повторная проверка 13 ноября](../audit/2026-11-13-full-library-recheck.ru.md) описывает семь исправлений, отсутствовавших в опубликованном теге `v5.0.5`:

- Обновление маршрута alias после запросов внешнего владения при разрешении.
- Согласование слотов исполнения параметров с обнаружением атрибутов.
- Обнаружение отложенных зависимостей, зарегистрированных вложенным callback внешнего контейнера, до завершения инвалидации.
- Учёт классов, объявленных резервной проверкой доступности, при проверке определений и селекторов атрибутов.
- Отклонение конфликтов источников HTTP DTO после такого резервного обнаружения.
- Фиксация плана атрибутов, действительно использованного обработчиками, вместо более позднего плана, обработчики которого не исполнялись.
- Совместное использование планов нативных статических callable для вариантов регистра имени класса без изменения сопоставления непрозрачных ID сервисов.

Bootstrap бенчмарков также выбирает классы и автозагружаемые вспомогательные функции из заданной рабочей копии при использовании оптимизированной карты классов в установленных зависимостях. Это исправление измерительного инструмента, а не заявленное ускорение приложения.

## Известные ограничения и следующая работа

За пределами patch остаются три дефекта жизненного цикла определений: прежние фабрики могут удерживаться после смены типа владельца определения; исключение деструктора освобождаемой фабрики может оставить `get()` и `make()` с разным состоянием; исключение деструктора кешированной обёртки может прервать инвалидацию семейства aliases. [Спецификация централизованного владения и освобождения](../plans/definition-owner-lifecycle.ru.md) готова для следующей major-ветки и прямо охватывает все три случая.

[Спецификация callbacks](../plans/php85-callbacks.ru.md) готова к реализации общего механизма связывания аргументов, `Transform`, callback-формы `SetUp` и детерминированного разрешения простых union-типов. Её условие E1 по-прежнему блокирует окончательный минимальный patch PHP и обещание поддержки затронутых нативных callable из trait. [План доступности атрибутов](../plans/attribute-availability-performance.ru.md) оставляет B2 условным направлением, требующим данных приложения и полного контракта синхронизации; он не утверждён как прозрачная оптимизация. Все планы сохраняют полные русские переводы.
