# Componenta DI v5.0.5

[English version](v5.0.5.md)

Этот patch-релиз включает исправления кеша, регистрации во время выполнения, времени жизни объектов и чтения payload запроса, проверенные после `v5.0.4`. Поддерживаемый публичный API и требование PHP `^8.4` сохранены. Протокол жизненного цикла владельцев определений, расширения callbacks PHP 8.5 и более широкая оптимизация проверки доступности атрибутов остаются предложениями.

## Версия и совместимость

Предыдущий стабильный релиз — [`v5.0.4`](https://github.com/componenta/di/releases/tag/v5.0.4). По [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html) исправления неправильного поведения без изменения поддерживаемого публичного API повышают patch-номер, поэтому этот релиз получает версию `v5.0.5`.

`composer.json` не изменился относительно `v5.0.4`: PHP остаётся `^8.4`, ограничения версий зависимостей Componenta сохранены, протоколы расширения во время выполнения не расширены. Добавленные и изменённые вспомогательные методы относятся к внутренней реализации. Различие между общим экземпляром из `get()` и новым экземпляром из `make()` сохранено. Для этих исправлений миграция корректной конфигурации не требуется.

## Исправленное поведение

| Область | Исправление |
| --- | --- |
| Обнаружение и композиция атрибутов | До проверки композиции планы завершают обнаружение на согласованной ревизии реестра. Если поздняя автозагрузка объявляет ранее недоступный атрибут, его учитывают классификация параметров и поиск обработчиков объекта. Класс, загруженный резервной проверкой интерфейса, меняет доступность в том же опросе; существующие попытки автозагрузки сохранены. |
| Reflection конкретного объекта | Планы из `ReflectionObject` обходят общие кеши с ключом только по имени класса. Это устраняет удержание исходного объекта и повторное использование его специфических метаданных для другого экземпляра. |
| Инвалидация aliases и делегаторов | Изменение отдельной цепочки сохраняет идентичность незатронутого исходного сервиса и соседних aliases. Замена привязки инвалидирует канонический источник, зафиксированный для этой регистрации; отложенные зависимые делегаторы определяются по графу aliases после проверки. Результат ранее начатого разрешения не может заново заполнить инвалидированную общую запись. |
| Повторный вход при регистрации делегатора | Проверка callable и обнаружение зависимостей завершаются до финальной проверки защищённого целевого ID. Автозагрузчик не может перенаправить alias на защищённый сервис и оставить на нём установленный делегатор. |
| Статические и magic-callable | Нативные статические callable, включая `__callStatic()`, не инвалидируются из-за изменения несвязанной сервисной привязки класса-владельца. Приоритет точного строкового ID сервиса сохранён. Обнаружение через резервную автозагрузку обрабатывается согласованно. |
| Время жизни данных magic-вызовов | Несуществующие имена методов используют нативную magic-диспетчеризацию без накопления отрицательной записи метаданных для каждого имени. Нативное связывание аргументов сохранено. |
| Ошибки регистрации | Исключения пакета сохраняются; внешние ошибки проверки и автозагрузки оборачиваются в `InvalidConfigurationException` с исходной причиной. Отказ до публикации сохраняет прежнюю регистрацию; независимо завершённые вложенные мутации остаются в силе. |
| Разобранный payload запроса | Пути payload проходят через вложенные объекты, в том числе смешанные структуры объектов и массивов. Отсутствующий путь и явный `null` по-прежнему различаются. |

[Аудит](../audit/2026-11-13-di-audit.md), [отчёт о согласованности кеша](../audit/2026-11-12-cache-parity-recheck.md) и контрактные тесты содержат воспроизведения и доказательства поведения. В диагностике удержания памяти для 50 000 разных magic-имён суммарный прирост по трём формам снизился примерно с 12,2 МБ до 1 880 байт. Это результат ограниченной диагностики, а не гарантия потребления памяти всего приложения.

## Проверка релиза

Отдельная копия проверенного исходного кода установлена с обычным `composer.json`, без workspace/path-репозиториев. Опубликованные `componenta/config v3.0.0`, `componenta/reflection v2.0.1` и `componenta/validation v3.0.1` успешно разрешились. Тем самым проверен режим зависимостей релизного workflow в дополнение к workspace-режиму обычного CI.

[Доказательства повторной проверки](../audit/2026-11-13-release-recheck.json) содержат ID деревьев исходного кода, версии и ссылки зависимостей, команды, вывод и ограничения проверки. Предыдущий [прогон CI для тех же деревьев production-кода и тестов](https://github.com/componenta/di/actions/runs/43428285178) прошёл Linux PHP 8.4/8.5 и Windows PHP 8.4; покрытие составило 90,5%, mutation score — 85,95%. Это результаты предыдущего прогона, которые не заменяют релизную проверку.

Существующий [Release workflow](../../.github/workflows/release.yml) публикует тег только после новых проверок точного коммита релиза: Linux PHP 8.4/8.5, Windows PHP 8.4, покрытие не ниже 80% и mutation score не ниже 85%. Зависимости устанавливаются из опубликованных пакетов. Workflow запускается коммитом `Release v5.0.5` в `main`.

## Известные ограничения 5.x и проверенные планы

Прежняя фабрика может остаться в памяти, когда у ID меняется тип владельца определения. Исключение из деструктора при освобождении старого определения или кешированной обёртки также может прервать инвалидацию после частичной фиксации мутации. Диагностические воспроизведения по-прежнему показывают это поведение; релиз не заявляет его исправление. [План жизненного цикла владельцев определений](../plans/definition-owner-lifecycle.ru.md) задаёт ответственность за удаление, удержание ссылок, завершение инвалидации до освобождения и отдельную категорию ошибки уже зафиксированной мутации. Изменения публичного протокола расширения относятся к следующей major-версии.

Опрос недоступных атрибутов также имеет измеримую стоимость. Более быстрый прототип A меняет наблюдаемое поведение автозагрузчика и не принят. Исправление корректности внутри одного опроса включено в 5.x; более широкая оптимизация заблокирована до решения о совместимости.

Все три [архитектурных плана](../plans/README.ru.md) перепроверены по навыку implementation-specification и получили полные русские переводы. Уточнены состояния holder и синхронная доставка ошибок, владение аргументами callbacks и нативные ограничения PHP, а также различие между завершёнными экспериментами и нерешёнными вопросами политики производительности. Предлагаемые API DI 6 в этот patch-релиз не входят.
