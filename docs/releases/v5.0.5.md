# Componenta DI v5.0.5

[Русская версия](v5.0.5.ru.md)

This patch release contains the cache, runtime-registration, lifetime, and request-payload corrections audited after `v5.0.4`. It keeps the supported public API and PHP requirement `^8.4`. The definition-owner lifecycle protocol, PHP 8.5 callback extensions, and a broader attribute-availability optimization remain proposals.

## Versioning and compatibility

The previous stable release is [`v5.0.4`](https://github.com/componenta/di/releases/tag/v5.0.4). Under [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html), fixes to incorrect behavior without a supported public API change increment the patch version, so this release is `v5.0.5`.

`composer.json` is unchanged from `v5.0.4`: PHP remains `^8.4`, existing Componenta dependency constraints remain intact, and no runtime extension protocol is widened. Added or changed helper methods are internal. Existing `get()` shared identity and `make()` fresh-instance semantics remain distinct. No migration of valid configuration is required for these fixes.

## Corrected behavior

| Area | Correction |
| --- | --- |
| Attribute discovery and composition | Plans finish discovery at a coherent registry revision before validating composition. A later autoload that declares an earlier unavailable attribute is observed in parameter classification and object-handler discovery. A class loaded during the fallback interface probe advances availability in that same poll, preserving the existing autoload attempts. |
| Object-specific reflection | Plans built from `ReflectionObject` bypass shared caches keyed only by class name, avoiding retention of a source object and reuse of object-specific metadata for a different instance. |
| Alias and delegator invalidation | Requested-pipeline changes preserve unaffected source and sibling shared identities. Binding replacement invalidates the canonical source captured for that registration, while deferred dependents are determined from the alias graph after validation. In-flight results cannot repopulate an invalidated shared entry. |
| Reentrant delegator registration | Callable validation and dependency discovery finish before a final protected-target check. An autoloader cannot retarget an alias to a protected service and leave an installed delegator behind. |
| Static and magic callables | Native static callables, including `__callStatic()`, are not spuriously invalidated by an unrelated service binding for the owner class. Exact string service IDs retain their existing precedence. Fallback autoload discovery is handled consistently. |
| Magic-call lifetime | Missing method names use native magic dispatch without accumulating one negative metadata entry per name. The native argument-binding behavior is preserved. |
| Registration failures | Package exceptions remain intact; foreign validation/autoload failures are wrapped in `InvalidConfigurationException` with the original cause. Pre-publication rejection preserves the existing registration; independently completed nested mutations remain committed. |
| Parsed request payload | Nested object segments are traversed when resolving payload paths, including mixed object/array structures. Missing paths and explicit `null` retain their distinct meanings. |

The [audit](../audit/2026-11-13-di-audit.md), [cache-parity report](../audit/2026-11-12-cache-parity-recheck.md), and contract tests record reproductions and behavioral evidence. The audit's retained-memory probe for 50,000 distinct magic names dropped from about 12.2 MB across its three forms to 1,880 bytes; that is a bounded diagnostic, not an application-wide memory guarantee.

## Known 5.x limitations and reviewed plans

An obsolete factory may remain retained when an ID changes definition-owner type. A destructor throwing while old definitions or cached wrappers are discarded can also interrupt invalidation after part of a mutation has committed. The diagnostic reproductions still demonstrate these behaviors; this release does not claim to fix them. The [definition-owner lifecycle plan](../plans/definition-owner-lifecycle.md) specifies removal ownership, retained references, completion of invalidation before release, and an explicit committed-failure category. Its public extension changes belong to the next major version.

Polling unavailable attributes also has a measured cost. The faster prototype A changes autoloader observations and was not adopted. The same-poll correctness correction is included in 5.x; the broader optimization remains blocked on a compatibility decision.

All three [architecture plans](../plans/README.md) were rechecked with the implementation-specification workflow and now have full Russian translations. The review clarified holder states and synchronous failure reporting, callback argument ownership and native PHP restrictions, and the difference between completed experiments and unresolved performance-policy decisions. Proposed DI 6 APIs are not part of this patch release.
