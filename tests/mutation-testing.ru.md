# Мутационное тестирование

[English version](mutation-testing.md)

Установите Composer-зависимости пакета для разработки и выполните:

```sh
composer test-mutation -- --parallel --processes=8
```

Команда собирает начальное покрытие одним процессом, затем проверяет мутации параллельно. Общий тайм-аут процесса Composer для этой команды отключён; Pest сохраняет отдельный лимит для каждой мутации. После сбора начального покрытия Xdebug в дочерних процессах отключается. Нужен драйвер покрытия PCOV или Xdebug; минимальный mutation score составляет 85%. Дополнительные параметры Pest, например `--path=src/Internal/functions.php`, позволяют ограничить проверку. Её score описывает только выбранные файлы.

При использовании Xdebug задайте в окружении команды `XDEBUG_MODE=coverage` и `COMPOSER_ALLOW_XDEBUG=1`, чтобы Composer не перезапустился без драйвера покрытия. Для PCOV эти переменные не нужны.

Используйте команду Composer вместо прямого вызова `pest --mutate`. Тестовый launcher откладывает загрузку DI-файла из Composer `autoload.files` до PHPUnit bootstrap, когда Pest уже может подставить изменённые функции. Команда также отключает CLI OPcache в родительском и дочерних процессах, чтобы ранее скомпилированный код не скрывал мутацию.

При выборе тестов используются целые тестовые классы, чтобы команды дочерних процессов укладывались в ограничения Windows. Это сохраняет все покрывающие тесты и может запускать дополнительные методы тех же классов. Покрытие строк исходника и порог score не меняются. Перезаписывается только временный mutation coverage report Pest.

Launcher явно задаёт PHP executable дочерних процессов, нормализует кавычки в фильтрах Pest и не передаёт PHPUnit служебные параметры mutation workers. Production autoloading не меняется. `MutationBootstrapContractTest` проверяет исходный файл и подмену, которая должна завершиться ошибкой ещё до выполнения тестов.

Выжившая мутация — кандидат для исследования, а не доказательство дефекта. Прежде чем добавлять тест или игнорировать мутацию, определите наблюдаемый контракт. Не снижайте порог ради успешного результата запуска.

Bootstrap self-check работает и внутри активной мутации. При запуске изолированных дочерних процессов он временно восстанавливает нативный file wrapper родителя, затем возвращает mutation substitution в `finally`. Это отделяет блокировки process pipes в Windows от file wrapper Pest; каждый дочерний процесс по-прежнему применяет собственную запрошенную подмену.

Mutation workers сохраняют PHP-конфигурацию родителя: `-c` или `-n`, каталог расширений и необходимые расширения. Перед генерацией мутаций launcher выполняет полный неизменённый suite той же worker-командой. Ошибка этого контрольного запуска прерывает mutation testing: сбои окружения worker не должны считаться обнаруженными мутациями.

Проверка mbstring использует выбранную worker-конфигурацию. Модуль, переданный родителю через CLI-флаги, сохраняется и при загруженном ini. Встроенный модуль или модуль, уже загружаемый worker ini, повторно не подключается.

Мутации деклараций и других строк без привязки к отдельным тестам выполняются полным suite через `MutationFallback`. При параллельном запуске эти проверки идут группами с запрошенным числом процессов. Результаты остаются в памяти текущего запуска и передаются Pest при обработке соответствующих мутаций. Отсутствие coverage metadata не подменяет фактический результат выполнения тестов. Покрытые строки не добавляются, исходные файлы не исключаются. Вывод контрольного запуска и каждого fallback worker сохраняется в `.phpunit.cache/mutation-workers/`.

Все работающие fallback workers опрашиваются, чтобы оба канала вывода продолжали читаться, пока другие процессы активны. У каждого worker сохраняется собственный тайм-аут с момента запуска. Поэтому worker с большим выводом может завершиться, не ожидая предыдущего процесса, а настоящее превышение лимита по-прежнему даёт `timeout`. Контрактные тесты используют реальные процессы и вывод, превышающий ёмкость pipe, для stdout и stderr; также проверяются успешный и неуспешный exit, содержимое отчётов и повторное использование primed results.

Pest включает timeout в свой score. При оценке порога отдельно разбирайте timeout и также указывайте долю мутаций, обнаруженных завершившимися тестовыми запусками.

По событию завершения mutation suite родитель записывает `.phpunit.cache/mutation-report.json`. Версионированный JSON содержит корень checkout и доступный commit, версии PHP и инструментов, аргументы команды, SHA-256 исходных файлов, исходные счётчики Pest и данные каждой мутации. Для каждой мутации сохраняются ID, относительный путь, строки, mutator, текстовый diff и result.

Поле `complete` требует результата для каждой выбранной мутации и проверки результатов дочерних процессов. Завершившийся процесс должен подтвердить установку подмены и начало завершения PHP. На POSIX родитель также проверяет, не прервал ли сигнал процесс для мутации на покрытой строке. Для тайм-аутов требуется подтверждённый запуск. Ошибка проверки даёт `worker_failure`, сбрасывает `pest_score` и останавливает проверку. При успешной проверке процессов отчёт сохраняет score Pest без изменений.

Длительность сохраняется в секундах только там, где её измерил Pest. Fallback processes не заполняют его timing fields, поэтому у них записывается `null` с причиной `not_recorded_by_pest`, а не вводящий в заблуждение ноль. Для выбранной, но не выполненной мутации используется причина `not_run`. Вывод fallback связан с ID через `.phpunit.cache/mutation-workers/<id>.log`; эти логи не описывают обычные Pest workers. В локальном worker-каталоге могут остаться файлы старых запусков: к текущей выбранной области относятся только ID из текущего manifest. CI начинает с чистого checkout.

Mutation ID включает абсолютный путь исходника. `--id=<id>` позволяет повторить проверку в том же checkout path, но ID из CI может не совпасть с ID в другом локальном каталоге. Для сопоставления используйте commit, относительный файл, mutator и diff; проверьте SHA исходника, версии PHP и инструментов. Поле `head` использует фактический Git checkout, а при невозможности определить его через Git — `GITHUB_SHA`. Хеши файлов собираются при завершении: не меняйте исходники во время запуска. Report не обнаруживает промежуточные изменения, не содержит полные изменённые исходники и не фиксирует scheduling или нагрузку машины. Поэтому timeout требует отдельного контролируемого повторения.

CI публикует manifest и fallback logs отдельным artifact `mutation-php-8.4`, даже если mutation step завершился ошибкой. Перед новым родительским запуском launcher удаляет предыдущий manifest; контрольный и mutation children его не удаляют и не перезаписывают. Если bootstrap, начальные тесты или runner завершаются ошибкой до finish event, нового manifest нет: artifact может содержать только доступные worker logs либо отсутствовать. Отсутствующий report не является успешным или полным mutation run.

## Нативные subprocess-контракты и выбор mutation tests

Cold-container fixtures выполняются в отдельных нативных PHP-процессах. Их `SubprocessAutoload` применяет унаследованную Pest mutation до загрузки цели, включая совпадающий Composer `autoload.files` entry. Исполненные дочерним процессом строки не попадают в coverage report родителя.

Поэтому mutation selection adapter объявляет следующие зависимости для мутаций уже покрытых строк:

| Исходник | Дополнительно зарегистрированный контракт | Проверяемая граница |
|---|---|---|
| `src/Container.php` | `ContainerColdMutationContractTest` | Проверка protected aliases при холодной загрузке |
| `src/ContainerFactory.php` | `ContainerFactoryCompletionContractTest` | Инициализация контейнера до возврата factory |

Каждый дополнительный test file должен быть зарегистрирован в текущем Pest suite. Перед сравнением пути приводятся к каноническому виду через `realpath()`. Ограниченный запуск, который не загружал указанный test file, не получает его selector и не загружает дополнительные тесты автоматически.

`P\Tests\Contract\ContainerColdMutationContractTest::` и `P\Tests\Contract\ContainerFactoryCompletionContractTest::` — generated class selectors закреплённой версии Pest 4. Это зависимости worker filter, а не утверждение, что тестовые классы исполнили соответствующие строки исходника в родительском процессе. Adapter уже использует временный mutation coverage file для передачи whole-class selectors в Pest; дополнительные selectors используют тот же механизм. Исходные файлы, executable lines и coverage hits не добавляются. Пустые и `null` line entries сохраняются. Входной coverage array не изменяется на месте.

`MutationCoverage::covers()` и fallback для uncovered mutants используют компактную маску измеренных покрытых строк, захваченную до добавления selectors. Это позволяет не удерживать значительно большую таблицу соответствий строк отдельным тестам во время проверки мутаций. Fallback policy и классификация covered/uncovered не меняются.

Объявления намеренно ограничены двумя перечисленными исходниками. Другие subprocess coverage boundaries требуют отдельного разбора; это не общая агрегация покрытия дочерних процессов. Существующие cold bootstrap/retry cases также могут выбираться через общий тестовый класс, если in-process test покрывает нужную строку. Однако это не устанавливает полное child line coverage для каждого исходника. При обновлении Pest или переименовании указанного contract file повторно проверьте generated selector и соответствующий ограниченный worker regression.

Первый regression использует настоящую `ForeachEmptyIterable` mutation цикла проверки protected aliases. Когда начальный suite содержит `RuntimeMutationContractTest` и `ContainerColdMutationContractTest`, измеренное покрытие выбирает только первый, и мутация выживает. Добавление cold selector вызывает падение существующего alias case: ожидаемая protected-target exception отсутствует, а публичный alias разрешается в `decorated-core`. Подмена идентичным исходником проходит. Запуск только `RuntimeMutationContractTest` сохраняет прежний selector и проходит identity control. Так проверяются поведение исходника и выбор тестов без искусственного добавления coverage нативному child.

Factory completion contract использует отказ холодного autoloader, чтобы проверить сообщение об ошибке инициализации collaborator до возврата контейнера, сохранение исходной причины и возможность повторной успешной попытки. Удаление завершающего `get(Config::class)` нарушает этот контракт. Другие тесты могут покрывать эту строку в родительском процессе, тогда как cold contract отсутствует среди её measured test IDs: его empty-factory case не достигает completion. Explicit factory mapping сохраняет зарегистрированный cold contract в worker selection для этой мутации. `MutationCoverageContractTest` проверяет оба source mappings, посторонний исходник, незарегистрированные контракты, неизменность входных данных и сохранение пустых и `null` line entries.
